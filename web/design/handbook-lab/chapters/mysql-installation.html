Applies to MySQL Server 8.4 LTS; the production baseline is RHEL 9 x86_64 with Oracle MySQL Community RPMs from the MySQL Yum repository. Separately licensed products and other platforms are identified explicitly.[1][72]

Installation

Choose one installation method

These package/service notes target RHEL 9, x86-64, Oracle MySQL Community 8.4 LTS RPMs. They are not Ubuntu/Debian or Windows commands. Enterprise packages require the corresponding entitlement/download source. Before installing, inventory existing MySQL/MariaDB packages, data and services; replacing an existing server is an upgrade/migration, not a fresh install.

Repository installation and GPG trust

  1. Obtain the current EL9 repository-configuration RPM from the official MySQL Yum download page linked by the installation manual. Its filename/build and signing key change; do not copy the old EL8 release-RPM URL or import every historical key.
  2. Verify the package signature and the signing-key fingerprint through the official download/signature instructions. Keep gpgcheck=1; a missing/expired key is not a reason to disable verification. rpm -K downloaded-package.rpm checks a downloaded RPM against trusted keys; a key imported from an unverified source does not prove authenticity.
  3. Install that verified repository package using dnf. Inspect /etc/yum.repos.d/mysql-community.repo and enable the 8.4 LTS server channel, with other server-series channels disabled. Verify the repository’s actual IDs; current guidance names mysql-8.4-lts-community.
  4. Inspect the transaction before accepting installation of mysql-community-server. DNF resolves dependencies. EL8’s module-disable step is specific to EL8 and must not be copied unconditionally to EL9.

Read-only inventory examples and the install command after those prerequisites:

dnf repolist enabled
rpm -qa 'mysql*' 'mariadb*'
sudo dnf install mysql-community-server

Do not add -y until the selected repository, architecture and package transaction have been reviewed. The RPM unit initializes an empty data directory on first start; confirm this is a deliberately new instance and that required storage is mounted. Start/manage it with the vendor systemd unit, then use the initial-password mechanism documented for that package and secure the root account. Do not copy initial passwords into scripts or notes.

Local RPM packages

Download matching 8.4 builds for EL9 from official distribution/archives, verify signatures, and use DNF on the complete selected local package set. Do not force RPM dependencies or mix EL8/EL9, Community/Enterprise or server-series packages.

Generic Linux archive

A generic tarball contains a prebuilt server/client layout, libraries, documentation and support files, not every host dependency or a guaranteed systemd unit. Match architecture/glibc and required libraries to the selected build. Verify the download, create a dedicated OS account, choose a new empty datadir, initialize with the selected server binary as documented, and secure the generated administrative account. Preserve package-managed installations separately. Supplied SysV examples are not modern systemd integration.

Use the configuration chapter for paths and a service decision checklist. Do not place downloaded configuration files directly over /etc/my.cnf.

RHEL package origin and support contract

The production baseline is RHEL 9 x86_64 with Oracle MySQL Community 8.4 LTS RPMs from Oracle’s MySQL Yum repository. Use a maintained RHEL 9 minor release and an approved current 8.4 maintenance build. Oracle’s platform matrix includes this OS/architecture. This is not a claim that a RHEL subscription supports Oracle’s independently supplied database RPMs; confirm the required vendor support entitlement separately.

RHEL also supplies MySQL through AppStream, with its own packaging and lifecycle: Red Hat documents 8.0 as the initial RHEL 9 stream and 8.4 from RHEL 9.6. Its mysql-server / dnf module install mysql:8.4/server route is an alternative, not a prerequisite to the selected mysql-community-server route. Both use a mysqld service name, which does not make their helper scripts, multiple-instance support or upgrade procedures interchangeable. Do not mix Red Hat and Oracle server packages or run AppStream module switching against this Oracle-RPM installation. Red Hat documents containers for its multiple-instance route; the named vendor template in these notes is the Oracle-RPM route.

Before approving a host, record /etc/redhat-release, uname -m, the enabled repository IDs, full installed package versions/vendor, and the installed unit/config file list. Resolve existing MariaDB/MySQL packages or enabled competing streams as a migration decision; do not force replacement or erase their data.

Complete the trust and first-start sequence

  1. Download the EL9 repository RPM and corresponding current public signing key through Oracle’s official HTTPS download/signature pages. Compare the full fingerprint/key material and validity to the vendor publication for the selected package; a familiar filename, short key ID or keyserver response alone is not trust. The GPG manual documents changing signing-key release boundaries, so no perpetual key-year URL is assumed here.
  2. After that independent check, import the reviewed key into the RPM keyring (a personal GPG keyring is not the same store). Check the repository RPM’s embedded signature before installation. In this example REPO_RPM must be set to the exact downloaded EL9 repository RPM, and mysql_pubkey.asc is the independently verified downloaded public key:
: "${REPO_RPM:?Set the exact verified EL9 repository RPM path}"
sudo rpm --import ./mysql_pubkey.asc
rpm --checksig "$REPO_RPM"

Stop unless the output confirms valid digests and signatures under the intended key; do not proceed on NOKEY, NOT OK, expiry or digest-only success. Only then install that file with sudo dnf install "$REPO_RPM". Inspect the installed repository configuration, keep gpgcheck=1, and enable only the intended 8.4 server series. Review available packages with dnf list --showduplicates mysql-community-server and the selected transaction/repository; record the approved full version. Do not disable signatures to work around a repository/key problem.

  1. Install mysql-community-server from the selected channel as described above. Inspect rpm -ql mysql-community-server, systemctl cat mysqld.service and effective option files. Before first start, deliberately keep classic connections local with bind_address=127.0.0.1; if X Protocol is not needed, configure mysqlx=OFF in the intended [mysqld] group. This avoids assuming that the classic bind also confines X Protocol. Confirm the intended empty datadir is on the required mounted storage; do not initialize an existing database.
  2. Validate options, then start without implicitly enabling boot startup:
sudo /usr/sbin/mysqld --validate-config
sudo systemctl start mysqld.service
systemctl status mysqld.service
sudo journalctl -u mysqld.service -b

The Oracle RPM helper initializes a deliberately empty datadir and writes the temporary root password to /var/log/mysqld.log. Read it privately with privileged access, never in shared transcripts. Run mysql_secure_installation interactively using that temporary password, review each prompt, set the required root credential, remove unnecessary anonymous/test access and prevent unwanted remote root access. Do not put the password in arguments, a SQL example or a recorded shell session.

  1. Reconnect with mysql --protocol=SOCKET --socket=/var/lib/mysql/mysql.sock --user=root --password and inspect SELECT VERSION(), @@version_comment, @@datadir, @@socket, @@port, @@server_uuid;. Confirm ss -ltn/ss -lx show only intended listeners; check logs, ownership and enforcing SELinux. Provision least-privilege application access, verified TLS and source-restricted firewall rules before changing the bind to a remote interface. Only after successful checks enable boot startup with sudo systemctl enable mysqld.service and rehearse the required mount/boot ordering.

For an already initialized production instance, review the package’s documented NO_INIT=true in /etc/sysconfig/mysql and required mount dependencies to prevent an absent mount being silently initialized. This is a shared package environment file: account for every named instance and its initial-provisioning workflow before changing it.
