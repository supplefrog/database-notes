Components

Process scheduling

Non-preemptive scheduling lets a running task keep the CPU until it exits, blocks or voluntarily yields. Preemptive scheduling can take the CPU away without that cooperation—for example when a higher-priority task becomes runnable. A fixed time slice is one policy, not the definition of preemption: Linux SCHED_FIFO has no time slice, whereas SCHED_RR does.[2][84]

Process control block

A process control block (PCB) is the textbook record of process state. Linux represents execution contexts with kernel task structures rather than a single portable PCB layout. The fields below describe the conceptual model, not a binary layout to inspect or edit.[117][122]

Field What it records
PID Process/task identity
State Running, runnable, sleeping, stopped, and other lifecycle states
Pointers Links to queues and related kernel objects
Priority Scheduling policy and priority information
Program counter Instruction location needed to resume execution
CPU registers Saved execution context
I/O information Open resources and pending/waiting operations
Accounting information CPU time and other usage statistics

The conceptual job queue is the collection of submitted jobs/processes awaiting or under system management; the ready queue contains tasks eligible to run; a device/wait queue contains tasks waiting for an event such as I/O completion. Linux has multiple scheduling and wait structures, not one universal queue of each kind. ps is a snapshot of process state, not a dump of all scheduler queues.[38][117]

Scheduler roles

  • Long-term/admission scheduling: decides which jobs enter a workload; a textbook role, not a separate required Linux scheduler daemon.
  • Short-term/CPU scheduling: selects a runnable task for a CPU. Dispatch changes its role from ready to running.
  • Medium-term scheduling: the textbook suspension/resumption role, sometimes associated with swapping.[117]

Swapping

A task blocked on I/O need not be swapped out. Linux normally reclaims memory at page granularity: discard reconstructible clean file-backed pages, write dirty file-backed pages to their backing file, or move eligible anonymous pages to swap. Swapping an entire process is a useful historical model, not a description of every Linux scheduling decision.[1]

Context switching

The kernel saves the outgoing task’s CPU execution state and restores the incoming task’s state. Switching address spaces may also change memory mappings and translation context; it does not copy all process memory into a PCB. Threads in the same process share an address space.[85][123]

Scheduling algorithms

The selection rules below are textbook models; SJN is also commonly called shortest job first (SJF).[84]

Model Selection rule
First come, first served (FCFS) Arrival order; typically non-preemptive
Shortest job next (SJN) Smallest estimated CPU burst; non-preemptive
Priority Highest eligible priority; can be preemptive or non-preemptive
Shortest remaining time (SRT) Preemptive counterpart of shortest-job scheduling
Round robin Rotate eligible tasks after a time quantum
Multilevel queue Separate workload queues, with a policy between and within queues; unlike multilevel feedback, this label alone does not imply moving tasks between queues.[136]

These are conceptual models, not interchangeable Linux command-line settings. Linux exposes policies such as SCHED_OTHER, SCHED_FIFO, SCHED_RR and SCHED_DEADLINE; normal scheduling internals depend on the kernel version. Real-time priorities can starve ordinary work and require a deliberate capacity and privilege policy.[2]

For observation and safe signalling, see process tools.
