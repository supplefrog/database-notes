Audit availability and setup

MySQL Enterprise Audit is commercial. Use the plugin and installation SQL shipped with the same server distribution/build. A third-party audit plugin has its own license, ABI, policy language and compatibility matrix; copying an arbitrary .so into plugin_dir is not an installation procedure.

The Enterprise installation script creates the plugin, filter tables and loadable functions. A bare INSTALL PLUGIN audit_log SONAME 'audit_log.so' alone does not establish the full filtering configuration. Follow the package’s audit_log_filter_linux_install.sql procedure with the documented administrator privileges, after checking for an existing installation. Back up the filter definitions and plan performance/retention/security requirements. Verify SHOW PLUGINS, filter tables and a controlled login/query event, then read the actual audit file. No sample audit output is assumed here.

Configuration reference

Parameter / interface 8.4 meaning
plugin-load / plugin-load-add Startup plugin loading; repeated plugin-load can replace the list. Prefer the documented complete installation path.
audit_log_policy Legacy mode’s ALL, LOGINS, QUERIES, NONE; rule-based filtering uses JSON filters instead. Not a universal runtime policy selector.
audit_log_file Audit path; protect ownership, free space and retention.
audit_log_format OLD or NEW XML formats, or JSON; XML is not the literal option value. Startup setting.
audit_log_rotate_on_size Size-triggered rotation, in bytes; use supported audit rotation/purge rather than uncoordinated file deletion.
audit_log_compression NONE or GZIP; verify format/installation prerequisites.
audit_log_encryption NONE or AES; requires an appropriate working keyring. AES256 is not the option token. Keep the keys required to read retained logs.
audit_log_include_accounts Legacy include-list behavior, not a replacement for rule filters.
audit_log_exclude_accounts Legacy exclusion list; review interaction with include lists rather than enabling both indiscriminately.
audit_log_filter_id Read-only identifier of the session’s assigned filter; not a command for selecting a policy.

Filters: replacements for old utility commands

The source’s mysqlauditadmin flags were not a valid 8.4 management API. Preserve their intended operations using the real interfaces below. Filter functions require the audit-administration privilege documented for the installed plugin. Start with a limited test account and verify events before broad assignment; logging SQL can capture sensitive data.

Source operation/flag Current interface and meaning
--list-filters Inspect mysql.audit_log_filter and account assignments in mysql.audit_log_user with authorized access.
--create-filter --name --filter audit_log_filter_set_filter(filter_name, json_definition) creates/replaces a named JSON filter. Validate its event rules.
--create-policy --name --filter --log No separate command with this contract; put event logging decisions in the filter JSON.
--apply-policy --name --user audit_log_filter_set_user(account, filter_name) assigns a filter to an account. The % assignment is a default and needs deliberate review.
--drop-filter --name audit_log_filter_remove_filter(filter_name) removes a filter and affects its assignments.
--drop-policy --name Remove/reassign affected account rules with audit_log_filter_remove_user(account) and manage named filters explicitly.

An example definition, not an instruction to log every production account:

SELECT audit_log_filter_set_filter('review_all_events', '{"filter":{"log":true}}');

Reading/searching audit logs

The old mysqlauditgrep task list remains relevant, but its guessed flags must not be treated as installed 8.4 commands. Use the documented audit_log_read/bookmark functions for compatible JSON logs or an access-controlled JSON parser; encrypted/compressed files need their supported reader/decryption workflow first.

Original option intent Equivalent review task
--pattern, -e Match the selected SQL/message field, not arbitrary raw lines across records.
--regexp Apply an explicit regular expression in the chosen analysis tool; do not assume SQL LIKE semantics.
--users Filter account/host fields, preserving identities exactly.
--start-date Inclusive starting timestamp; account for log timezone.
--end-date Explicit ending boundary; document inclusive/exclusive handling.
--event-type Filter documented event classes/subclasses for that log format.
--query-type Filter statement classifications where present; do not infer SQL type by a fragile string prefix.
--status Check recorded success/error status with that event schema.
--file-stats Calculate counts/size/time span with the analysis tool; not a server audit-policy flag.
--license Inspect the selected tool’s license/version separately; it does not validate the audit trail.

Secure rotation archives, separate audit administration from ordinary application access, and test disk-full/failure behavior. The general query log is not a drop-in compliance audit system.
