File system management

Filesystems organize names and metadata in directories and allocate storage for file data. Ownership, permissions, labels and mount options affect access; they do not replace backups.[23]

Encryption

At-rest encryption protects stored data under a defined key-management model; in-transit encryption, such as SSH or TLS, protects communications. One does not automatically provide the other. An unlocked encrypted filesystem remains accessible to authorized processes; protect encryption keys and recovery material separately.[83][30]

Authorization

Discretionary access control (DAC)

Traditional Unix DAC uses ownership plus owner/group/other mode bits (rwx). Access Control Lists can express additional per-user/per-group permissions; the basic mode bits are not themselves an arbitrary ACL. Directory write/search permissions govern directory-entry creation and removal; file write permission governs modifying file content.[19][88]

See permissions and umask.

Security

Authentication

Authentication verifies an asserted identity. Passwords, biometrics and SSH public-key authentication are different mechanisms. PAM-aware services can delegate relevant checks to configured PAM stacks; SSH keys also require correct server policy and account authorization.[7][30]

Authorization

SELinux

SELinux implements mandatory access control using labels and policy enforced in the kernel. In normal access checks, passing DAC is not enough: SELinux can still deny access. SELinux does not simply override ownership permissions to grant access. Policy can restrict a process’s access to files, network ports and other resources; roles and domains are policy concepts, not synonyms for Unix groups.[143]

Firewall

RHEL 9 commonly uses firewalld with zones, services, ports and optional rich rules to control traffic. A rule can combine a source address with a service or port restriction. Packet filtering, SELinux application permissions and service authentication are separate controls. Before changing firewall rules remotely, retain console access and verify both the intended application path and the management path; a rule that drops SSH can end the maintenance session.[57]

Enforcing SELinux: diagnose before changing policy

On RHEL 9, semanage is provided by policycoreutils-python-utils; install it through the approved Red Hat repositories if missing. Keep enforcement enabled. Inspect the service’s actual OS permissions, process context and file labels before assuming a database authentication or firewall problem:[143]

getenforce
ps -eZ
sudo semanage fcontext -l -C
sudo semanage port -l
sudo ausearch -m AVC,USER_AVC,SELINUX_ERR,USER_SELINUX_ERR -ts recent

Record the actual denied process, operation and target. For a custom service path, compare ls -lZ with matchpathcon /actual/path; check parent-directory search access and ACLs as well as file modes. semanage fcontext changes persistent path mappings; restorecon applies those mappings to existing objects. A one-off chcon is not a durable replacement. When moving a whole standard directory tree, a reviewed semanage fcontext -a -e OLD_ROOT NEW_ROOT equivalence mapping can preserve distinct labels for data, sockets and other children. These uppercase arguments are placeholders for verified paths, not literal directory names. Inspect existing local rules before adding/modifying/removing one.[143]

Ports have policy types too: inspect the current assignment before adding a nondefault service port, and never reassign a port owned by another service merely to silence a denial. Labels must match the actual daemon’s documented policy, not a type copied from another database. Re-test the denied operation, persistent label restoration and the next controlled service restart. Stop if the policy need is unexplained; do not leave SELinux permissive/disabled or blindly install audit2allow output. Preserve the original local mapping for targeted rollback.[143]

Firewall changes: narrow rule, live test, then persistence

Inspect firewall-cmd --get-active-zones, the actual zone’s runtime --list-all, and its --permanent --list-all before editing. The default zone is not necessarily the interface’s zone. A service definition admits its listed ports; a database’s nondefault port is not automatically covered. An additional narrow allow rule does not remove existing broader access.[57][142]

For a separately authorized IPv4 example, replace public, 192.0.2.0/24 and 3306 with the actual zone, approved source network and listener port. Test temporarily before persistence:

sudo firewall-cmd --zone=public --add-rich-rule='rule family="ipv4" source address="192.0.2.0/24" port port="3306" protocol="tcp" accept' --timeout=300

The timeout is runtime-only and cannot be combined with --permanent. Verify a fresh application connection from an allowed host, denial from an unapproved host, and a new management session before expiry. Check IPv6 separately when present. An open socket alone does not establish reachability or authenticated TLS.[142]

If accepted, remove the timed copy if still active, add the identical non-timed runtime rule and add that exact rule with --permanent. Use --query-rich-rule for both stores and test again. Avoid --runtime-to-permanent unless every other transient runtime change is intended to persist. A reload replaces runtime policy with permanent policy; schedule/test it rather than casually discarding unrelated runtime rules. Rollback uses --remove-rich-rule for only the introduced rule in both stores, preserving SSH and other existing rules. Confirm intended access survives the next controlled reload/reboot; never stop the firewall as the fix.[142][57]

Password policy

These examples target RHEL 9 local accounts. Directory-backed identities may have policy elsewhere. Account changes require delegated administrative authority.

File or command Meaning
/etc/login.defs Defaults used by relevant account-management tools, including some password-aging defaults; not a universal password-quality policy and not a retroactive update of every existing account
/etc/shadow Protected password-hash/lock fields and per-account aging information; do not disclose or make it world-readable
chage -m 7 -M 90 -W 7 username Example: minimum 7 days, maximum 90 days, warning 7 days before expiry. Apply only if this matches the organization’s policy, not as a universal recommendation
chage -l username Inspect the resulting aging policy
/etc/pam.d/ Service-specific PAM stacks
/etc/security/pwquality.conf Password-quality settings used when the relevant PAM module is actually in the password-change stack.[121]

Password aging and creation defaults are defined by the account tools, not one universal PAM setting.[64][65]

The password field is conventionally called “encrypted password” in shadow(5), but normal local password verification uses a salted password hash, not recoverable plaintext encryption. A lock marker and password expiry are not equivalent to disabling every possible authentication method.[34][62]

On RHEL 9, use the supported authselect workflow for managed authentication profiles rather than editing generated PAM files blindly. Back up policy/configuration and keep a known-working privileged session or console before authentication changes; test a separate login and restore the prior configuration if it fails.[66][7]

Reset root password via GRUB

Authorized recovery only, on a RHEL 9 system you administer. This interrupts the machine and bypasses the normal login path. Obtain maintenance approval, a verified recovery backup and physical or trusted out-of-band console access. Confirm any bootloader credential and encrypted-volume unlock material are available. If boot policy prevents editing, use the organization’s approved rescue process rather than disabling security controls.

  1. Reboot into the GRUB menu, select the intended RHEL entry and press e.
  2. Append rd.break to the line beginning with linux. This is a temporary edit for this boot; do not save it as a permanent kernel argument.
  3. Press Ctrl+x. At the switch_root prompt, remount the installed root and enter it:
mount -o remount,rw /sysroot
chroot /sysroot
passwd root
touch /.autorelabel
exit
exit

Enter the replacement password only at passwd’s prompts. touch /.autorelabel is run inside the chroot, so it marks the installed root for SELinux relabelling. The first exit leaves the chroot; the second leaves the early-boot shell and resumes boot. Relabelling may take time and cause a further reboot; do not interrupt it.[8]

After normal boot, verify an authorized login, whoami, expected SELinux mode with getenforce, and required services.[143] Confirm the temporary rd.break argument is absent on the next normal boot. If recovery fails, return to the approved console/rescue process; do not leave an early-boot shell or permissive security configuration as the operating state. See boot stages.
