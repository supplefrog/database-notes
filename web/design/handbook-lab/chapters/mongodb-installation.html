Package prerequisites

Host mutation on an authorized fresh host only. The baseline is RHEL 9 x86_64, current supported RHEL errata, systemd, SELinux Enforcing, and MongoDB Community 8.0.29 vendor RPMs. This is MongoDB’s repository, not a Red Hat AppStream package or a Red Hat support entitlement. RHEL 9 x86_64 is in MongoDB’s supported platform matrix.[104] Verify AVX-capable supported CPU, OS/kernel advisories, storage capacity and mount persistence; prefer XFS for WiredTiger. Keep RHEL kernel/glibc/OpenSSL maintained through the organization’s Red Hat repositories. Do not substitute libraries from another distribution.[62]

cat /etc/redhat-release
uname -m
uname -r
lscpu
getenforce
rpm -q glibc openssl-libs selinux-policy-targeted
sudo dnf repolist --enabled

Stop if this is not the approved RHEL 9 x86_64 platform or if existing MongoDB data/packages are present. These are fresh provisioning commands, not an in-place migration. Use sudo for OS work and a separate MongoDB identity for database work. Have authorized RHEL repositories available for dependencies.

Fetch MongoDB’s 8.0 signing key, inspect its full fingerprint, and compare it with the independently approved MongoDB key record before import. RPM trust is machine-wide, unlike a per-repository keyring; gpgcheck=1 requires signed packages but is not repository-metadata signing. Do not bypass verification with --nogpgcheck.[104]

sudo dnf install curl gnupg2 python3-dnf-plugin-versionlock
curl -fsSLo server-8.0.asc https://pgp.mongodb.com/server-8.0.asc
gpg --show-keys --with-fingerprint server-8.0.asc
# STOP here until the complete fingerprint has been independently approved.
sudo rpm --import server-8.0.asc

Create root-owned /etc/yum.repos.d/mongodb-org-8.0.repo (0644). The RHEL 9 repository tab gives this URL; do not substitute the default tab’s RHEL 10 URL.[113]

[mongodb-org-8.0]
name=MongoDB Repository
baseurl=https://repo.mongodb.org/yum/redhat/9/mongodb-org/8.0/x86_64/
gpgcheck=1
enabled=1
gpgkey=https://pgp.mongodb.com/server-8.0.asc

The published repository metadata contains these exact NEVRAs: server/router 8.0.29-1.el9.x86_64, shell 2.10.0-1.el8.x86_64, Tools 100.17.0-1.x86_64. The shell’s el8 release tag is actually published in the RHEL 9 repository; do not invent an el9 shell build or infer its NEVRA from its shorter RPM filename. Server/router require OpenSSL 3 and glibc 2.34 symbols; DNF resolves the maintained RHEL dependencies.[106]

sudo dnf --refresh --disablerepo='*' --enablerepo=mongodb-org-8.0 \
  list --showduplicates mongodb-org-server mongodb-org-mongos mongodb-mongosh mongodb-database-tools
sudo dnf install mongodb-org-server-8.0.29-1.el9.x86_64 \
  mongodb-mongosh-2.10.0-1.el8.x86_64 mongodb-database-tools-100.17.0-1.x86_64
sudo systemctl disable --now mongod
rpm -q mongodb-org-server mongodb-mongosh mongodb-database-tools
sudo dnf versionlock add mongodb-org-server mongodb-mongosh mongodb-database-tools
sudo dnf versionlock list

Review the transaction’s repository/version/signature prompts; omit automatic yes. The server RPM enables boot start on a fresh install, so disable/stop it until bootstrap is accepted. Upgrading an active server package may try to restart it: package work is part of the maintenance window.[100] These are direct components, not a partly pinned metapackage. Install mongodb-org-mongos-8.0.29-1.el9.x86_64 only on router hosts as explained in sharding. If an exact package is unavailable, stop; review a replacement or retrieve an approved retained artifact with signature/checksum verification. Version locks select installed package NEVRAs and need scheduled security review, not permanent neglect.[112]

Keep SELinux enforcing

The official policy covers standard RPM/systemd mongod installations on RHEL 9: /usr/bin/mongod, /var/lib/mongo, /var/log/mongodb, /run/mongodb, package user/unit and standard MongoDB ports. It does not cover mongos, shell/tools, arbitrary extra services or relocated paths. Changing those means a site-reviewed policy/integration, not disabling SELinux. The installation manual explicitly warns custom settings are outside the supplied policy’s standard contract.[103][104]

Install the documented policy build prerequisites plus RHEL’s management/diagnostic tools. Build as an ordinary user from a reviewed immutable revision; only installation needs sudo. The revision below is the reviewed source, not permission to ignore future policy/security fixes.[103][110]

sudo dnf install git make checkpolicy policycoreutils selinux-policy-devel \
  policycoreutils-python-utils setools-console audit
git clone https://github.com/mongodb/mongodb-selinux
cd mongodb-selinux
git checkout --detach 18181652362a46fd4511a56f20c4055712deb252
git rev-parse HEAD
# Review source/diff and retain its revision with the deployment record.
make
sudo make install
sudo semodule -l
sudo restorecon -Rv /usr/bin/mongod /var/lib/mongo /var/log/mongodb
sudo restorecon -v /usr/lib/systemd/system/mongod.service /etc/mongod.conf
sudo semanage port -l | grep '^mongod_port_t'
getenforce

Require Enforcing, the installed mongodb policy module, and appropriate port labels before start. After start, inspect ps -eZ for mongod_t and Audit denials, not just an active unit. The policy README’s automatic-application wording is not proof the module is already installed; the versioned RPM spec does not install that policy, so the explicit build/install and readback above remain required.[100][103][108]

Custom paths/ports and restore services follow instance policy integration. Keep startup blocked until that host’s confinement and file access have been checked.

Configure before first start

Package contract: the RHEL installation page currently contains conflicting generic account/directory prose; the tagged RPM specification, unit and configuration agree on the values used here. Inspect the installed artifacts if they differ; do not create a second account/path based on that prose.[100][102][113]

The server RPM supplies mongod:mongod, /var/lib/mongo, /var/log/mongodb, /etc/mongod.conf and /usr/lib/systemd/system/mongod.service.[100][101][102] Complete the enforcing SELinux setup above and keep the service stopped/disabled while preparing a fresh instance. Start with authorization already enabled and bind only loopback; the localhost exception allows creation of the first administrator when no users or roles exist.[7][104]

sudo systemctl stop mongod
sudo install -d -o mongod -g mongod -m 700 /var/lib/mongo
sudo install -d -o mongod -g mongod -m 750 /var/log/mongodb
sudo systemctl cat mongod
sudo systemctl show mongod -p User -p Group -p ExecStart -p Environment \
  -p LimitNOFILE -p LimitNPROC -p LimitMEMLOCK -p TasksMax

The vendor unit reads optional /etc/sysconfig/mongod, sets MONGODB_CONFIG_OVERRIDE_NOFORK=1 and GLIBC_TUNABLES=glibc.pthread.rseq=0, creates /run/mongodb, and supplies LimitNOFILE=64000, LimitNPROC=64000, unlimited locked memory and TasksMax=infinity. Preserve these versioned integration settings; shell ulimit and login limits do not configure a systemd service. Inspect local drop-ins/environment overrides and the running process limits. Do not add fork: true or a competing PID-file model.[101]

Save this as /etc/mongod.conf, root:mongod 0640, readable by the service. It intentionally starts a standalone; replication is introduced separately. Do not put passwords here.[6]

storage:
  dbPath: /var/lib/mongo
systemLog:
  destination: file
  path: /var/log/mongodb/mongod.log
  logAppend: true
net:
  port: 27017
  bindIp: 127.0.0.1
security:
  authorization: enabled

sudo chown root:mongod /etc/mongod.conf
sudo chmod 640 /etc/mongod.conf
sudo restorecon -v /etc/mongod.conf
sudo systemctl start mongod
sudo systemctl status mongod --no-pager
sudo ps -eZ | grep mongod
sudo ausearch -m AVC,USER_AVC -ts recent
sudo journalctl -u mongod -n 80 --no-pager
mongosh --host 127.0.0.1 --port 27017

In this local shell, create the first user. passwordPrompt() reads a secret interactively instead of embedding it in a command/history file. Choose a long, unique secret in the organization’s password manager.[7][18]

use admin
db.createUser({
  user: "useradmin",
  pwd: passwordPrompt(),
  roles: [{role: "userAdminAnyDatabase", db: "admin"}]
});
exit

Reconnect authenticated; omit a password value so the shell prompts:

mongosh --host 127.0.0.1 --port 27017 --username useradmin --authenticationDatabase admin

use admin
db.runCommand({connectionStatus: 1, showPrivileges: true});
db.createUser({user: "operator", pwd: passwordPrompt(), roles: [
  {role: "clusterAdmin", db: "admin"},
  {role: "readWrite", db: "shop"},
  {role: "dbAdmin", db: "shop"}
]});
db.createUser({user: "monitor", pwd: passwordPrompt(), roles: [
  {role: "clusterMonitor", db: "admin"}
]});
db.createUser({user: "backup", pwd: passwordPrompt(), roles: [
  {role: "backup", db: "admin"}
]});
db.createUser({user: "restore", pwd: passwordPrompt(), roles: [
  {role: "restore", db: "admin"}
]});

userAdminAnyDatabase can grant powerful roles and must be protected like a superuser, even though it is not the daily data account. operator is a deliberately privileged training/operations identity, not an application login. More narrowly scoped application/monitoring roles are in users and privileges.[18][85]

Prove readiness and close bootstrap

mongod --version
mongosh --version
mongodump --version
mongosh --host 127.0.0.1 --port 27017 --username operator --authenticationDatabase admin

db.getSiblingDB("admin").runCommand({ping: 1});
db.getSiblingDB("admin").runCommand({getCmdLineOpts: 1});
db.getSiblingDB("shop").getCollectionInfos();

Expected observations: service active, correct binary/tool versions, intended listener/path, authenticated privileged command succeeds. In a separate unauthenticated local shell, a protected operation such as listing shop collections must be rejected. ping alone is not an authorization test. Then enable boot start with sudo systemctl enable mongod.[6][9][104]

If first-user creation returns Unauthorized, an existing user/role may already have closed the exception. Authenticate with the existing administrator; do not delete the data directory or open an unauthenticated network listener to “fix” it. If startup fails, preserve logs and use startup diagnosis. Keep a known-good config copy for rollback; a config rollback does not undo created users or application data.[7]

Before remote clients, configure TLS and private network access. The loopback bootstrap here is not a remote production connection recipe.

Binary distribution alternative

If RPMs cannot be used, select the RHEL 9 x86_64 Community tarball for the approved server version from MongoDB’s archive and verify its official checksum/signature. The RHEL tarball guide lists libcurl, openssl and xz-libs as dependencies (sudo dnf install libcurl openssl xz-libs); shell/Tools remain separate releases. Extract into a versioned directory such as /opt/mongodb/8.0.29. Tarballs create no service account, config, directories or unit: provision these explicitly and keep foreground systemd supervision, limits and glibc environment aligned with the reviewed RPM unit.[101][105]

A binary under /opt is outside the standard policy file-context mapping. Before starting, have the SELinux owner review persistent executable/data/log/unit labels and domain transition plus any required narrowly scoped policy. Verify a confined process under enforcing mode on the exact RHEL build. Do not copy the guide’s conflicting generic account paragraph or use an unconfined tarball process as an installation shortcut. The preferred baseline remains vendor RPMs.[103][107][110]

Retain the exact artifact and digest in the deployment record. Do not replace /usr/bin/mongod underneath a package-managed service, install an archive for a different OpenSSL/glibc target, or infer that successful extraction proves support. Reuse the same secure bootstrap/readiness checks. Package installation is preferred here because it supplies the integration that the binary path leaves to you.[105][104]
