Architecture, editions and tools

Applies to MySQL Server 8.4 LTS; the production baseline is RHEL 9 x86_64 with Oracle MySQL Community RPMs from the MySQL Yum repository. Separately licensed products and other platforms are identified explicitly.[1][72]

MySQL Architecture

Logical

Logical architecture diagram — external reference. Reuse rights are unresolved; the explanation below does not depend on the image.

Client

Connectors implement the MySQL protocol for applications. mysql is a command-line client; Workbench is a separate GUI and does not require the mysql CLI to establish every connection.

[2][103]

Server

  1. Startup: initialize the server and load privilege information; startup is not a user-issued FLUSH PRIVILEGES operation.
  2. Connection: clients can use TCP or a local transport such as a Unix socket. For classic-protocol TCP, the server greeting advertises capabilities and authentication information. A TLS-capable client sends SSLRequest, negotiates TLS, then sends authentication data inside that transport.
TLS stage What to check
ClientHello Client advertises supported protocol versions and cryptographic parameters.
Server negotiation Server selects compatible parameters and proves its identity with its certificate and handshake authentication. Exact message ordering differs between TLS 1.2 and 1.3.
Certificate validation VERIFY_CA checks the trusted issuer; VERIFY_IDENTITY also checks the requested hostname against the certificate. Merely encrypting a connection does not verify the server.
Key agreement Modern TLS uses negotiated key agreement; do not teach RSA-encrypted premaster-secret exchange as the universal handshake. TLS 1.3 does not use that legacy RSA key exchange.
Finished messages Authenticate the handshake and establish traffic keys; application data is encrypted and integrity protected.
Client certificate Optional unless the account/policy requires it; distinct from password authentication.
  1. Authentication: the handshake response identifies the user and client capabilities. The server matches an account including its Host portion, chooses the account’s authentication plugin, and may continue or switch the plugin exchange. The response is plugin-dependent, not universally a password hash. Success yields OK; failure yields ERR. caching_sha2_password is the normal 8.4 choice; update old clients rather than re-enabling legacy authentication by default.

[2][3][70][103]

4. Connection manager: the default one-thread-per-connection model can reuse a cached thread or create one. Enterprise Thread Pool changes scheduling; neither model makes a client connection a separate mysqld process.

[84]

5. Authorization: the server checks the account’s privileges for requested operations; a successful login does not authorize every query. 6. Parsing: SQL text is tokenized and checked against the grammar, producing internal query structures. This is a conceptual pipeline, not a claim that every AST node is itself a SQL operation or that privilege checking occurs only once before parsing.

[148][32]

7. Optimization: the optimizer considers applicable access paths and transformations, index use, join ordering and supported join methods such as nested-loop/hash joins. Statistics and cardinality estimates feed cost estimates; they are not measured runtime. It chooses among the plans it explores, not an exhaustive guaranteed global optimum.

The InnoDB adaptive hash index is an internal engine optimization, not a named SQL index hint. Use EXPLAIN and, for a safe bounded query, EXPLAIN ANALYZE to compare estimates with execution; the latter executes the query.

[32][34][9][139]

8. Execution and storage engines: the executor requests rows through the engine interface. InnoDB reads cached pages or fetches them from storage. Changes dirty buffer-pool pages and generate redo; commit durability and later page flushing are different events.

Cache Meaning
Table open cache Reuses open table objects; file-descriptor consumption depends on engine and configuration.
Data dictionary object cache Reuses metadata; distinguish it from InnoDB’s buffer pool.
Historical query cache Deprecated in 5.7.20 and removed in 8.0. No MySQL 8.4 server query cache setting exists. Application caching requires explicit invalidation and consistency decisions.
Key cache Caches MyISAM index blocks, not InnoDB rows.
InnoDB buffer pool Caches index and data pages, including clean and dirty pages.

[4][7][86]
