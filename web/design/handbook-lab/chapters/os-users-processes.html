Local users and groups

These are RHEL 9 local-account tools. Identity-service accounts need their own administration workflow. Before changing identity, record the UID/GID and groups, check running processes and file ownership, and preserve an independent administrative login. Deleting an account or reassigning an ID can orphan files or grant unintended access.[8][35]

Command Meaning
useradd USER Create a local account using configured defaults; set the intended options explicitly
adduser USER Distribution-dependent frontend: RHEL commonly provides useradd-equivalent behavior; Debian’s adduser is a higher-level, usually interactive tool
useradd -g GROUP USER Choose an existing primary group; the default primary-group policy varies
useradd -G group1,group2 USER Choose supplementary groups
useradd -m USER Create the home directory if needed
useradd -m -d /home/custom USER Set and create a custom home path; verify path ownership and SELinux labeling
passwd USER Set/change a local password interactively; never put it on a command line
usermod -g GROUP USER Change primary group; audit ownership implications
usermod -G group1,group2 USER Replace supplementary membership with the specified list
usermod -aG group1,group2 USER Append supplementary memberships without discarding existing ones
usermod -d /home/new USER Change recorded home path; does not move contents unless the appropriate move option is used
userdel USER Delete the account; does not by itself remove all files or terminate every owned workload.[104]
gpasswd -M user1,user2,user3 GROUP Replace the group’s member list, not merely append users
groups USER / id USER Inspect groups / UID, primary GID and supplementary groups
groupadd GROUP Create a group.[105]
groupadd -g 1003 GROUP Example explicit GID; verify that it is available and permitted by local policy
groupmod -n NEW OLD Rename a group.[106]
groupmod -g NEWGID GROUP Change GID; existing file ownership may need a carefully scoped migration
groupdel GROUP Remove a group; check primary-group dependencies and files first.[107]

Verify the resulting account with id and a new login session. Existing processes do not automatically gain a newly assigned supplementary group. Avoid removing the only working administrator or assigning IDs already used by files/central identities.[35][36][63]

Processes, signals and jobs

Start with a read-only process listing and verify owner, PID and command before signalling. A PID can be reused; recheck immediately before the action. For a managed service, prefer its documented service-stop procedure to killing a random child.[38][37]

Command or key Meaning
ps Snapshot of selected processes; selection and output depend on options
ps ux BSD-style user format, including the invoking user’s processes without a controlling terminal; avoid the ambiguous mixed spelling ps -ux
ps a BSD-style selection expands to terminal-associated processes of other users
ps -a Unix-style selection of terminal-associated processes excluding session leaders
ps aux Common BSD-style all-process snapshot in user format
kill PID / kill -s TERM PID Send SIGTERM; default action is termination, but a program can handle or ignore it
kill -s KILL PID SIGKILL; cannot be caught, blocked or ignored. No application cleanup; use only after an approved graceful-stop attempt and data-risk assessment
kill -s CONT PID Continue a stopped process; does not choose foreground/background terminal membership
kill -l List signal names/numbers for the platform
pkill -x NAME Signal exact matching process names; can still affect multiple instances. Inspect matches first rather than using broad patterns.[108]
Ctrl+c Terminal normally sends SIGINT to the foreground process group; default termination, catchable/ignorable
Ctrl+z Terminal normally sends SIGTSTP, default stop; catchable/ignorable. The shell regains control; the job is stopped, not running in the background
Ctrl+\ Terminal normally sends SIGQUIT, whose default action is termination with a core dump when enabled; dumps can contain secrets
jobs List jobs known to this shell, including stopped and background-running jobs
fg %1 Bring shell job 1 to the foreground and continue it if stopped
bg %1 Continue shell job 1 in the background; terminal access may still stop it
crontab -l / crontab -e List/edit the current user’s schedule; crontab -u USER -l targets another user when authorized
* * * * * command User-crontab minute, hour, day-of-month, month, day-of-week, then command
@monthly command Cronie monthly shorthand; first day of the month at midnight
sar -u 1 3 sysstat CPU-utilization samples, one second apart, three reports.[115]

Use signal names in portable recipes; numbers such as 9/15/18/20 are architecture-dependent except where a particular platform defines them. SIGSTOP, unlike SIGTSTP, cannot be caught or ignored. Shell fg/bg are job-control operations, not a property chosen by SIGCONT.[37][18]

Cron runs with a limited environment: use deliberate paths, logging and permissions; avoid scheduling a command that overlaps its previous run or exposes credentials. In a user crontab there is no extra username field. If both day-of-month and day-of-week are restricted, Cronie normally matches either field, not their intersection. sar history requires configured data collection; installing a tool does not create past data.[56][51]

top

top is an interactive view, not a historical audit. The following keys refer to procps-ng; consult its h help for the installed build.[39]

Command/key Meaning
top -p PID Monitor a selected PID (a list can be supplied as supported)
o, then COMMAND=chrome Add an “other filter” expression; comparison/filter behavior follows top’s rules
L Locate a string in the current display; not the same operation as filtering
k Prompt to signal a process; an authorized state-changing action
r Prompt to renice a process; privilege limits apply
h Interactive help

Filtering is not inherently superior to locating: filter to restrict visible rows, locate to navigate. For k or r, verify the process and consider service impact before confirming.

Memory and I/O monitoring

Command Meaning
vmstat 1 3 Process, memory, paging, I/O and CPU statistics; rate counters in the first report are averages since boot, then interval averages; process and memory counts are instantaneous in both
iostat 1 3 sysstat CPU/device I/O statistics; first report covers since boot, subsequent reports the interval. Select the correct device layer

A busy logical device may share underlying physical storage with others. Correlate memory pressure, paging, I/O latency and application behavior rather than diagnosing from one utilization number.[71][72][1]

Resource limits

Interface Meaning
ulimit -S -a / ulimit -H -a Show this Bash process’s soft / hard resource limits
ulimit -S -n 4096 Example request for a soft open-file limit, allowed only up to the applicable hard limit; applies to this shell and its future children
ulimit -H -n VALUE Change the hard limit where permitted; an unprivileged shell generally cannot raise it again after lowering it
/etc/security/limits.conf and /etc/security/limits.d/ Limits for sessions that actually invoke pam_limits; not a global retroactive switch for every running process
systemd LimitNOFILE= Per-service process limit, configured in the service’s unit/drop-in
systemd MemoryMax=, CPUQuota= Cgroup-backed resource controls, different from ulimit process limits

Choose limits from the workload’s needs, current usage and host budget; a larger limit is not free capacity. Back up prior policy, test with a fresh relevant login or a planned service restart, and verify the target process’s effective limits. Editing PAM limits does not automatically modify system services or existing sessions.[18][46][55]

For grouped CPU/memory/I/O budgets, see cgroups. systemd resource-control options should be checked against the installed manager/controller configuration.[47]

Package cleanup and RPM database recovery

On RHEL 9, yum is a compatibility interface to DNF. dnf autoremove selects packages marked as dependencies that are no longer required according to package-manager state; that does not prove the application owner no longer needs them.[50]

Preview before any approved cleanup:

sudo dnf --assumeno autoremove

Review every proposed removal and dependency, protect explicitly required packages, and have a tested recovery path before applying a removal transaction. Verify applications afterward.

rpm --rebuilddb / rpmdb --rebuilddb rebuilds the installed-package database; it does not reinstall files or repair arbitrary filesystem damage. Use only for a diagnosed database problem under the distribution’s recovery procedure: prevent concurrent package transactions, take a recoverable backup of the actual configured database, preserve logs and investigate storage errors first. rpmdb --verifydb verifies database integrity; it is not package-file verification. Recheck database queries and application/package health after recovery. Do not delete database files as a speculative “fix.”[49]
