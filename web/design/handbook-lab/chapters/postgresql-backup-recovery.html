Backup and recovery

Decide what must be recoverable

RPO is acceptable lost work; RTO is acceptable time to restore service. A successful backup command measures neither. Budget detection, provisioning, download/decryption, restore, WAL replay, validation and routing—not just copy time. Replication is not backup: it can faithfully reproduce a mistaken delete.[33][38]

Method Captures Recovery boundary
pg_dump One database’s logical definitions/data in a consistent snapshot Selective restore and major migration; no cluster globals or WAL replay.
pg_dumpall --globals-only Roles and tablespaces Complement to per-database dumps; protect role hashes if included.
Full pg_basebackup with WAL Whole physical cluster, including all databases/tablespaces Same-major physical restore on a compatible platform.
Base backup + continuous WAL archive Cluster state plus later changes PITR to a reachable target, only with an unbroken required WAL chain.
Consistent storage snapshot All required volumes at one coordinated point, or a clean stopped copy A casual live directory copy is not a consistent backup.

Keep multiple generations in separate failure domains, encrypt off-host copies and restrict delete rights. Retain encryption keys, recovery credentials, extension packages, configs, certificate chains and archive metadata separately from a failed host. Test restoring with the keys the recovery team can actually retrieve. Never delete archive WAL solely by file age: retain all WAL needed by the oldest retained recoverable base and every recovery/replica consumer.[31][33]

Make and restore a logical backup

This bounded procedure backs up adminlab on postgresql-18 and restores it to a fresh, isolated postgresql-18-restore cluster on port 5543. It assumes no user tablespaces, the fixture roles/objects, local peer administration and a secure backup filesystem. Check existing cluster names/ports first. Do not overwrite an existing restore cluster or database.

  1. Create a fresh directory owned by postgres with mode 0700; the example is /srv/pg-backups/logical-drill. Use a unique job directory for every real run, umask 077, and the major-18 binaries. As the OS postgres account:
/usr/pgsql-18/bin/pg_dump -h /run/postgresql -p 5432 \
  -U postgres -d adminlab --format=custom \
  --file=/srv/pg-backups/logical-drill/adminlab.dump
/usr/pgsql-18/bin/pg_dumpall -h /run/postgresql -p 5432 \
  -U postgres --globals-only --no-role-passwords \
  --file=/srv/pg-backups/logical-drill/globals.sql
/usr/pgsql-18/bin/pg_restore --list \
  /srv/pg-backups/logical-drill/adminlab.dump

Require zero exit status and retain stderr for both exports; --list only reads the archive catalog, not every data block. A dump uses one database snapshot and can coexist with writes, but holds locks and can conflict with DDL. Multiple database dumps are not automatically one cluster-wide transaction snapshot.[29][31]

Option Use Restriction
-Fc / --format=custom Compressed, selective restore archive Parallel dump requires directory format instead.
-Fd -j 4 Parallel directory dump Destination must not already exist; adds connections and load.
--schema-only / --data-only Definitions or contents only Not a complete backup; dependencies still matter.
-n schema / -t pattern Filter objects Dependencies outside selection are not necessarily included.
pg_restore --exit-on-error Fail instead of continuing past errors Inspect failures; partial work otherwise may remain.
pg_restore --single-transaction Atomic bounded restore Cannot combine with parallel jobs; large restores may need a different plan.
--no-owner --no-acl Restore under new ownership without grants Useful for deliberate remapping, not permission-fidelity validation.
--clean / --create Drop objects / use database name in archive Destructive; intentionally absent from this drill.
  1. Register postgresql-18-restore.service using the separate-unit procedure, with PGDATA=/var/lib/pgsql/18/restore, an empty owned directory and mount ordering. Initialize only this empty logical-restore target with the bootstrap locale/checksum/auth options and postgresql-18-setup initdb postgresql-18-restore. In its config set listen_addresses = '', port = 5543, unix_socket_directories = '/run/postgresql', logging_collector = on, log_directory = 'log'; use the bootstrap local peer rules. No firewalld rule is needed because TCP is disabled. Apply/verify labels before startup.[100][102]
sudo restorecon -Rv /var/lib/pgsql/18/restore
sudo systemctl start postgresql-18-restore.service
sudo -u postgres /usr/pgsql-18/bin/psql -X -h /run/postgresql -p 5543 -d postgres \
  -c 'SHOW data_directory;'
  1. Inspect globals.sql as sensitive executable SQL. For this fixture, prepare a reviewed copy omitting only the already-existing bootstrap CREATE ROLE postgres and its bootstrap-specific role alterations; do not remove the notes_* definitions or membership grants. Stop if unexpected role/tablespace collisions exist. --no-role-passwords deliberately means restored login roles need password reprovisioning before use. On a general restore, review tablespace locations so they cannot target live storage.[31]
# Run these as OS postgres; the reviewed file is readable only to recovery staff.
/usr/pgsql-18/bin/psql -X -v ON_ERROR_STOP=1 -h /run/postgresql -p 5543 -d postgres \
  -f /srv/pg-backups/logical-drill/globals-reviewed.sql
/usr/pgsql-18/bin/createdb -h /run/postgresql -p 5543 -U postgres --template=template0 --owner=notes_owner adminlab
/usr/pgsql-18/bin/psql -X -v ON_ERROR_STOP=1 -h /run/postgresql -p 5543 -d adminlab \
  -c 'REVOKE ALL ON DATABASE adminlab FROM PUBLIC; GRANT CONNECT ON DATABASE adminlab TO notes_read, notes_write;'
/usr/pgsql-18/bin/pg_restore -h /run/postgresql -p 5543 -U postgres -d adminlab --exit-on-error \
  --single-transaction /srv/pg-backups/logical-drill/adminlab.dump
/usr/pgsql-18/bin/psql -X -v ON_ERROR_STOP=1 -h /run/postgresql -p 5543 -d adminlab -c 'ANALYZE;'

Install every required extension binary first. The fixture has no third-party extension dependency, but a later pg_stat_statements installation must also exist on the target. Inspect archive SQL before restoring from an untrusted server: a dump can execute source-defined functions/code with the restore account’s authority. A failed atomic restore leaves the pre-created database; investigate rather than blindly rerun into it. Discard/recreate only the verified empty drill database after preserving error evidence.[29][30]

  1. Validate data and privilege behavior using the acceptance checks, provision temporary test credentials through the approved secret channel if needed, then sudo systemctl stop postgresql-18-restore.service. Do not route applications to it. Retain a drill report and securely retire the copy under policy.

Take a full physical base backup

Use PostgreSQL 18 tools against the 18 server. The baseline below intentionally excludes external tablespaces: inspect pg_tablespace first and stop if any user tablespace exists. For those clusters use a complete reviewed mapping for every external path with --tablespace-mapping=old=new or tar archives and an isolated host. Plain-format backups otherwise use the source’s absolute tablespace paths—a dangerous same-host surprise.[32]

The backup account needs replication capability and a matching HBA rule. Here OS postgres connects over the local socket using the bootstrap replication peer rule; no network superuser exposure is added. Check wal_level is replica or higher and enough max_wal_senders are available: --wal-method=stream uses a second connection.[32]

As administrator, provision empty /srv/pg-backups/base-drill owned by postgres, mode 0700, with enough free space. Then as OS postgres:

/usr/pgsql-18/bin/pg_basebackup \
  --host=/run/postgresql --port=5432 --username=postgres \
  --pgdata=/srv/pg-backups/base-drill --format=plain \
  --wal-method=stream --checkpoint=spread --progress
/usr/pgsql-18/bin/pg_verifybackup /srv/pg-backups/base-drill
Option Meaning / reason
--wal-method=stream Includes WAL needed to make the base consistent; temporary slot protection is used when supported and no permanent slot was requested.
--checkpoint=spread Spreads checkpoint work; fast can create an I/O burst.
--format=plain Direct physical file layout; safest here only because external tablespaces were excluded.
--write-recovery-conf / -R Creates standby settings; not used for a standalone backup.
--no-sync Skips durable file synchronization; do not use for real backups.
--incremental A different backup chain requiring manifests/WAL summaries and combination before restore; not what this full-backup procedure does.

A manifest check catches many missing/corrupt files, not every possible server/application failure. Use matching major tools for WAL verification and perform an actual isolated restore. Preserve the completed backup read-only; never start the only backup directory itself.[32][35]

PGDG config/HBA/auto.conf normally reside inside PGDATA, so the physical backup includes them; inspect and neutralize source-specific settings before restore. External includes, systemd units/drop-ins, tmpfiles definitions, SELinux local mappings, firewalld rules and any certificates/secrets outside PGDATA still require separate protected backup.[100] Also retain roles’ operational secrets, TLS material, extension versions, system identifier, start/end times, tablespace map and archive/timeline metadata. Do not include secrets in a world-readable job log.

Rehearse PITR with a named target

PITR needs a base backup plus continuous WAL from its starting point through the target. A dump archive cannot substitute. This local, no-tablespace exercise uses core’s example basic_archive module to learn the chain; it is not an off-site production backup system. Production archiving needs monitored durable storage, collision-safe/idempotent delivery, encryption, retention and restore-tested tooling.[33][67]

  1. Before the physical backup above, create a new archive directory /srv/pg-archive/main owned by postgres mode 0700 on persistent storage. Install the approved postgresql18-contrib RPM and verify /usr/pgsql-18/lib/basic_archive.so with rpm -ql postgresql18-contrib.[101] The server writes this custom archive path, so check current policy and add a narrow persistent data label, then apply it; do not label a whole backup filesystem indiscriminately:[102][104]
sudo semanage fcontext -a -t postgresql_db_t '/srv/pg-archive/main(/.*)?'
sudo restorecon -Rv /srv/pg-archive/main

Use -a only when the exact local mapping does not already exist; review a conflicting mapping rather than overwrite it. Verify owner/mode, all parent traversal and mount readiness; add RequiresMountsFor=/srv/pg-archive/main to the source unit and reload systemd. Configure the source:

wal_level = replica
archive_mode = on
archive_command = ''
archive_library = 'basic_archive'
basic_archive.archive_directory = '/srv/pg-archive/main'

Restart for archive_mode/any startup settings; inspect the log and pg_stat_archiver. Preserve wal_level = logical if logical replication already needs it; the minimum here is replica, not an instruction to downgrade a working configuration. Do not set archive_command and archive_library simultaneously. Use a different archive namespace per cluster identity, never a shared directory for unrelated primaries.[33][34]

  1. Complete and verify the full base backup. Only then, while fixture writers are quiesced, capture baseline counts/sums and the order-1 state. As superuser create a uniquely named restore point and force completed WAL to archive:
SELECT pg_create_restore_point('adminlab_before_change');
SELECT pg_switch_wal();
SELECT archived_count, last_archived_wal, last_archived_time,
       failed_count, last_failed_wal, last_failed_time
FROM pg_stat_archiver;

Wait for the relevant segment to be archived and verify the archive storage, not merely a non-null historic timestamp. Archive the job’s target name, source timeline and baseline results. Optionally change the fixture afterward to make reversal observable. Do not reuse this target name in a real run: recovery stops at the first matching restore point after backup.[23][33]

  1. Use a separate copy of /srv/pg-backups/base-drill at /srv/pg-restore/main, owned by postgres mode 0700. The target must be empty, port 5543 unused, no logical postgresql-18-restore drill running, and no live tablespace paths shared. Verify the copy with pg_verifybackup before modifying recovery configuration. Keep the original base/archive unchanged.

  2. Remove any inherited standby.signal from the restore copy only if present. Save its postgresql.auto.conf outside the restored PGDATA and replace it with an empty file owned by postgres mode 0600, so source connection/archive settings cannot override isolation. Save and replace any inherited main/HBA config in the copy. Use the existing tmpfiles-managed /run/postgresql socket directory with the distinct 5543 filename; keep TCP disabled. Put this new postgresql.conf in the restore PGDATA:

data_directory = '/srv/pg-restore/main'
hba_file = '/srv/pg-restore/main/pg_hba.conf'
listen_addresses = ''
port = 5543
unix_socket_directories = '/run/postgresql'
hot_standby = on
archive_mode = off
restore_command = 'cp /srv/pg-archive/main/%f %p'
recovery_target_name = 'adminlab_before_change'
recovery_target_timeline = 'current'
recovery_target_action = 'pause'

Create pg_hba.conf containing only local all postgres peer. Review compatibility settings from the source before starting: recovery’s max_connections, max_worker_processes, max_wal_senders, max_prepared_transactions and max_locks_per_transaction must not be lower than the source values where required. Install required extension libraries and deliberately choose any preload entries; do not blindly inherit a network or external side-effect configuration.[74]

Create recovery.signal as OS postgres in the restore copy only. Register postgresql-18-pitr.service from the inspected vendor unit using multiple instances, with PGDATA=/srv/pg-restore/main and RequiresMountsFor=/srv/pg-restore/main /srv/pg-archive/main. Skip initdb: this is already restored physical data. Keep it disabled at boot. Before launch, create the protected parent/data/log directories and map the copy persistently to the normal PGDATA label tree; do not let a file copy’s old labels silently define access.[100][102]

sudo semanage fcontext -a -e /var/lib/pgsql/18/data /srv/pg-restore/main
sudo restorecon -Rv /srv/pg-restore/main
sudo systemctl daemon-reload
sudo systemctl cat postgresql-18-pitr.service

Configure logging_collector = on, log_directory = 'log' in the copy; make PGDATA/log owned by postgres mode 0700 and verify its label. Then:

sudo -u postgres touch /srv/pg-restore/main/recovery.signal
sudo systemctl start postgresql-18-pitr.service
sudo -u postgres /usr/pgsql-18/bin/psql -X \
  -h /run/postgresql -p 5543 -d adminlab

Verify the intended confined postgresql_t process domain, file labels and absence of relevant AVC denials; journal startup diagnostics belong to postgresql-18-pitr, collector logs to the restored PGDATA/log. The simple restore command copies from a read-only archive to PostgreSQL’s requested file and must fail for absent files; never return success for an unsuccessful restore. The example restricts recovery to the backup’s current timeline; for a post-failover target select the documented descendant timeline and retain its history files. latest is not a substitute for deciding which history is correct.[33][34]

  1. Follow journalctl -u postgresql-18-pitr.service and the copy’s collector log. Missing required WAL or an unreached target is failure, not permission to promote early. When the target is reached, verify:
SELECT pg_is_in_recovery(), pg_is_wal_replay_paused(), pg_last_wal_replay_lsn();
SELECT count(*), sum(amount) FROM notes.orders;
SELECT order_id, status, amount FROM notes.orders WHERE order_id = 1;

Compare to the recorded pre-change baseline. A pause allows read-only checks before accepting the recovery point. If the point is too early, a later target may be replayed after stop/reconfiguration; to go backward, restore a fresh base copy. For an approved standalone recovery, SELECT pg_wal_replay_resume(); at the reached pause ends targeted recovery; confirm pg_is_in_recovery() is false and record the new timeline. For a drill, sudo systemctl stop postgresql-18-pitr.service and retain evidence.[34]

Target choice Required precision
recovery_target_name Unique restore point after backup completion.
recovery_target_time Timestamp with explicit UTC offset; inclusivity and transaction commit boundary matter.
recovery_target_lsn Known WAL location from the intended timeline.
recovery_target_xid Known transaction ID; not a wall-clock ordering shortcut.

Set one target selector, not several. Default inclusive behavior applies to time/XID/LSN; for an unwanted committed transaction choose/test the intended boundary explicitly. The selected target cannot precede the base backup’s recoverable state.[34]

Prove the restored service is usable

Validation is acceptance work, not invented command output. Record source snapshot/target, tool versions, backup checksums/manifests, exit codes, elapsed restore stages and each comparison.

  • Identity and recovery: correct system identifier for physical copies; intended major/port/path; target reached; expected primary/standby state; no source connections or live file paths reused.
  • Structure: schemas, extensions/versions, constraints, indexes, functions/triggers, owners and grants. Check invalid indexes and unvalidated constraints rather than counting only tables.
  • Data: per-table counts, null/range checks, totals and deterministic keyed exports/checksums against the same snapshot/target. A count against a source that kept changing is not a valid baseline.
  • Integrity: pg_verifybackup before physical restore; optionally pg_amcheck with installed amcheck and appropriate privileges after start. Checksum/structure checks do not establish business correctness.[35][66]
  • Application: representative reads, join results, a rollback-wrapped write, identity sequence next values, role-denial tests, time zone/collation behavior, external integrations safely disabled.
  • Operations: new backups/archiving, monitoring, alerting and secret recovery work; measured RPO/RTO meet the objective before switching traffic.

For the fixture, these read-only catalog checks make structure acceptance explicit. Run in the restored adminlab as an administrator; investigate every returned invalid index or unvalidated constraint, including any documented exception inherited from the source.[28][71]

SELECT indexrelid::regclass, indisvalid, indisready
FROM pg_index WHERE NOT indisvalid OR NOT indisready;
SELECT conrelid::regclass, conname, contype
FROM pg_constraint WHERE NOT convalidated AND conrelid <> 0;
SELECT extname, extversion FROM pg_extension ORDER BY extname;

The socket-only logical drill permits only matching OS identities through peer. To exercise the restored notes_app login itself, provision its credentials and temporarily enable a specifically approved loopback/TLS rule and listener, or provide a matching OS test identity; do not switch the drill to trust. A superuser’s SET ROLE notes_app can test grants, but cannot prove login authentication. PITR remains read-only while paused, so defer write/sequence smoke tests until an approved promotion on an isolated copy.[14][34]

Logical migration generally loads into the same or newer major; an older pg_dump refuses a newer server, and downgrade restore compatibility is not promised. Physical file/WAL formats are major-specific. Use the target-major dump/restore tools for a planned major migration and read intervening release notes.[29][36]

If checks fail, keep the production source unchanged, preserve the failed copy/logs and retry from a clean target after diagnosis. After a real cutover accepts writes, reverting to the old snapshot loses those writes unless reconciled. Keep source log rotation, WAL archive retention and backup retention separate: never rm WAL from PGDATA and never treat archiver success as proof the off-site copy or decryption key is available.
