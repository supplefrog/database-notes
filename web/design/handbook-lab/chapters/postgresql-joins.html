Inner join

An inner join keeps only rows that find a partner. Here, the customer id is the shared fact: orders.customer_id points to customers.id.

SELECT c.name, o.id AS order_id, o.total
FROM customers AS c
INNER JOIN orders AS o ON o.customer_id = c.id
ORDER BY c.id, o.id;

name order_id total
Ada 101 42
Ada 102 18
Grace 103 35

Ada appears twice because she has two orders. Linus is absent because an inner join has no row to return for a customer without an order.

Left join

A left join preserves every row from the table on the left. Put customers there when the question is “which customers have—or have not—ordered?”

SELECT c.name, o.id AS order_id, o.total
FROM customers AS c
LEFT JOIN orders AS o ON o.customer_id = c.id
ORDER BY c.id, o.id;

name order_id total
Ada 101 42
Ada 102 18
Grace 103 35
Linus NULL NULL

NULL is useful information here: Linus exists, but no matching order does. It is not zero and it is not an empty string.

Filter placement

The location of a filter changes a left join. A WHERE clause runs after the join, so this query removes both low-value orders and the unmatched Linus row:

↩ Figure 

SELECT c.name, o.total
FROM customers AS c
LEFT JOIN orders AS o ON o.customer_id = c.id
WHERE o.total > 30
ORDER BY c.id, o.id;

It returns Ada’s 42 order and Grace’s 35 order: 2 rows. Move the same condition into ON when you want all customers but only qualifying order matches:

SELECT c.name, o.total
FROM customers AS c
LEFT JOIN orders AS o
  ON o.customer_id = c.id AND o.total > 30
ORDER BY c.id, o.id;

That version returns 3 customer rows: Ada with 42, Grace with 35, and Linus with NULL. Ada’s 18 order no longer qualifies as a match. The practical rule is to say the question aloud: “filter the final rows” suggests WHERE; “limit what may match” suggests ON.

Practice

Move o.total > 30 between WHERE and ON in the left-join examples above. Predict which people remain, then compare your prediction with the result rows described in this lesson.
