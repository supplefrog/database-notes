Architecture, editions and tools

Applies to MySQL Server 8.4 LTS; the production baseline is RHEL 9 x86_64 with Oracle MySQL Community RPMs from the MySQL Yum repository. Separately licensed products and other platforms are identified explicitly.[1][72]

Physical

Executables and package layout

On RHEL 9 x86-64 RPM installations, client programs commonly live in /usr/bin and the server in /usr/sbin; basedir is not synonymous with /usr/bin. Generic tarballs use a different base directory. Check the package file list rather than guessing paths.

[18][88]

Client Apps Use
mysql CLI client
mysqladmin CLI for quick server management - status, processlist, kill, flush (reload) tables/logs/privileges, create/drop db, shutdown
mysqlbinlog Read binary logs
myisamlog Read MyISAM log
mysqlcheck -c check -a analyze -o optimize db [table_name]

| mysql_config_editor | Saves obfuscated credentials in .mylogin.cnf; restrict filesystem access. It is not strong encryption or a secrets vault. Password entry is prompted. |

Server Apps Use
mysqld Server

[19]

| mysqldumpslow | Summarize slow query logs to prioritize queries for tuning | | mysql_secure_installation | Set root password, remove anonymous users, disallow remote root login, remove test databases, reload privilege tables | | mysql_tzinfo_to_sql | Load system time zones into mysql schema | | my_print_defaults | Print options in options groups of option files |

Client utilities are separate programs with separate option syntax. mysqlimport uses LOAD DATA conventions: filenames map to tables and delimiter/escaping settings must match the source file; a CSV extension does not set those automatically. mysqlcheck --optimize can rebuild/lock tables and is not a harmless read-only diagnostic. mysqlslap generates workload and can create/drop its test schema: use only a disposable environment with explicit reviewed targets. myisamlog reads MyISAM logs, not the server binary log. my_print_defaults can disclose sensitive option values; keep its output private. mysql_migrate_keyring is a versioned offline component-key migration tool, not proof that encrypted tables have been migrated safely. Check each program’s packaged availability and official reference.

Optional and historical utilities

The following names remain useful when reading old runbooks. They are not an 8.4 installation checklist. MySQL Utilities 1.x was a separate, Python-based historical suite; do not install it as the operating layer for 8.4. Use current server SQL, MySQL Shell and supported topology tools. Third-party projects require separate maintenance and compatibility review.

Utility retained from the source Original task Current approach
mysqltuner Configuration recommendations Third-party heuristic script, not Oracle support advice; validate each proposal against workload measurements.
mysqlreport Human-readable status reports Historical third-party reporting; use status variables, Performance Schema and sys.
mysqlauditadmin Audit administration Enterprise Audit filter functions and rotation/reader interfaces.
mysqlauditgrep Search audit logs JSON-aware log analysis or Enterprise Audit reader functions.
mysqldbcompare Structure/data comparison Schema diff plus bounded data reconciliation; row counts alone are insufficient.
mysqldbcopy Database copy Shell dump/load or another tested logical migration.
mysqldbexport Export definitions/data mysqldump or Shell dump utilities.
mysqldbimport Import exported objects mysql for SQL dumps; Shell util.loadDump for Shell dump format.
mysqldiff Schema differences Compare normalized DDL with explicit definers, collation and routine handling.
mysqldiskusage Disk estimates information_schema.tables estimates plus actual storage measurement.
mysqlfailover Automatic failover InnoDB Cluster/AdminAPI/Router for appropriate supported topology, not automatic replacement of arbitrary asynchronous topology.
mysqlfrm Reconstruct .frm definitions Historical pre-8.0 metadata; 8.4 uses the transactional data dictionary, not .frm.
mysqlindexcheck Redundant-index checks sys.schema_redundant_indexes and measured workload review.
mysqlmetagrep Metadata search Information Schema queries.
mysqlprocgrep Session search Performance Schema process list or sys.processlist.
mysqlreplicate Configure replication Versioned CHANGE REPLICATION SOURCE TO procedure.
mysqlrpladmin Topology administration Current replication statements and AdminAPI where applicable.
mysqlrplcheck Replication checks Status tables, error/lag monitoring and independent data reconciliation.
mysqlrplshow Display topology Explicit topology inventory and supported cluster tooling.
mysqlserverclone Instance copying Shell logical copy/dump/load or the server Clone plugin, with overwrite checks.
mysqlserverinfo Server information Variables, status and package/version inventory.
mysqluc Utilities console Historical suite launcher; not mysqlsh.
mysqluserclone Copy users/grants Review SHOW CREATE USER/SHOW GRANTS, roles and authentication compatibility; do not copy mysql.user files.

Schemas and storage: logical objects are not one file each

Typical RPM data directory: /var/lib/mysql. Query @@datadir on the actual instance. Paths can be configured; do not edit or delete live server files.

Logical objects                         Typical 8.4 persistence
user schema/
  InnoDB tables                         .ibd for file-per-table; shared tablespaces also possible
  MyISAM tables                         .MYD data and .MYI indexes; metadata in .sdi
  procedures / functions                transactional data dictionary, not one routine file
  triggers                              dictionary metadata, not legacy .TRG files
  views                                 dictionary metadata, not materialized query results
mysql schema
  account/grant tables                  mysql.user, db, tables_priv, columns_priv, roles, ...
  protected dictionary tables           schemata, tables, columns, indexes, routines, events, ...
  persistence                           mysql.ibd contains dictionary and mysql system tables
information_schema
  metadata / privilege views            exposed by server; no user-managed per-view data files
performance_schema
  runtime instrumentation tables        engine-managed in-memory data; .sdi metadata may exist
sys
  diagnostic views, procedures/functions wrappers over monitoring information
  sys_config table                      persistent configuration (not every sys view is a file)

MySQL 8.4 does not use .frm, .TRG or .par as the old metadata model. Protected dictionary tables are not a supported direct-query API: use Information Schema and SHOW. The original sysconfig.ibd name was inaccurate; sys_config is the table name and its physical placement is not a portable administration API.

Non-schema files

Configured datadir (example /var/lib/mysql)
  ibdata1                 InnoDB system tablespace: change buffer and possible shared table data
  mysql.ibd               transactional dictionary and mysql system tables
  #innodb_redo/           active and spare redo files
  undo_001, undo_002       default separate undo tablespaces
  #ib_<page-size>_*.dblwr  doublewrite files (location configurable)
  #innodb_temp/           pooled session temporary tablespaces
  ibtmp1                  global temporary tablespace: temporary-table rollback segments
  auto.cnf                server UUID; not a configuration template to duplicate
  mysqld-auto.cnf          persisted system-variable settings; server-managed
  binlog files + index    binary-log changes for replication/PITR
  relay files + index     replica's received events
  mysql.sock + .lock      Unix socket and ownership lock when configured here
Outside or inside datadir, according to configuration
  error log               startup/runtime diagnostics
  general query log       connection and statement activity; sensitive, potentially costly
  slow query log          statements meeting configured thresholds/filters
  /etc/my.cnf             RPM option file, not a database data file

The InnoDB DDL log supports crash-safe DDL internally; it is not a general text log of all DDL statements. Binary, relay, redo and undo logs serve different recovery purposes. Do not use logrotate or manual deletion for managed database log files. The socket is created for a running local listener; verify server ownership before investigating stale socket/lock files.
