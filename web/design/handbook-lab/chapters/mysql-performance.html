Performance Monitoring / Tuning

Plans, traces and indexes

Substitute an existing table/condition/index in the schematic statements below. On production, ANALYZE TABLE can affect plans and acquire locks; EXPLAIN ANALYZE executes the statement and can be expensive. Rehearse with a bounded SELECT on representative test data before applying changes.

ANALYZE TABLE your_table;
EXPLAIN FORMAT=JSON SELECT * FROM your_table WHERE your_condition;
EXPLAIN ANALYZE SELECT * FROM your_table WHERE your_condition;

Estimated costs/rows are not elapsed runtime. EXPLAIN ANALYZE provides actual timings/rows/loops in TREE format in this target, not an assurance that every supported EXPLAIN form can be executed safely.

For a single-session optimizer trace, save the prior settings and read the trace immediately after the statement:

SET @old_trace = @@session.optimizer_trace;
SET SESSION optimizer_trace='enabled=on';
SELECT * FROM your_table WHERE your_condition;
SELECT TRACE FROM information_schema.OPTIMIZER_TRACE\G
SET SESSION optimizer_trace=@old_trace;

Trace output can contain sensitive SQL. Statement execution and trace collection add work.

Operation Schematic SQL and interpretation
Suggest eligible indexes SELECT * FROM your_table USE INDEX (idx_name) WHERE your_condition; restricts considered named indexes but does not force their use; a table scan remains possible.
Stronger index hint FORCE INDEX (idx_name) changes scan cost treatment; measure rather than assume it improves the query. Index hints can become stale as data changes.
Disable index merge in this session Save @@session.optimizer_switch, then SET SESSION optimizer_switch='index_merge=off';. Restore the saved string after the comparison.
Reset defaults SET SESSION optimizer_switch='default'; resets defaults, not necessarily the session’s original custom settings.
Inspect switches SHOW SESSION VARIABLES LIKE 'optimizer_switch';
List indexes SHOW INDEX FROM your_table;
Add candidate covering index CREATE INDEX idx_covering ON your_table(col1, col2, col3); only covers queries whose needed columns fit; column order matters for predicates/order/grouping.
Remove an index DROP INDEX idx_name ON your_table; only after checking constraints and workload dependence; plan DDL resource/lock costs and a recreation path.

Compare plans, latency distribution, rows examined, write overhead and storage before/after. A full scan is not automatically a missing-index defect; it can be cheapest for small tables or broad predicates.

sys schema

These are diagnostic views, not independent copies of application data. Their results depend on enabled instrumentation and collection/reset history.

View Meaning and caution
sys.user_summary User-level statement, I/O and connection aggregates.
sys.user_summary_by_file_io File I/O operations and latency by user.
sys.innodb_buffer_stats_by_table Buffer-page information grouped by schema/table. Querying this view can itself harm production performance; reproduce on a test instance unless its cost has been explicitly accepted.
sys.schema_tables_with_full_table_scans Reports table-access statistics with full scans; a scan is not automatically an indexing defect.
sys.processlist Detailed current session/process information, based on Performance Schema.
