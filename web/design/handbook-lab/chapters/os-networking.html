Networking

Examples use RHEL 9 with NetworkManager. Interface names such as enp1s0 are examples; discover the actual interface and active connection profile before changes. Read-only inspection:

nmcli device status
nmcli connection show --active
ip address show
ss -tuln

Connection changes can disconnect you. For authorized maintenance, retain out-of-band console access, record the active profile/address/routes/DNS, back up relevant profile configuration, and prepare a tested rollback before changing a remote interface. Do not release/flush the interface carrying your only administrative session.

Command Meaning
nmcli NetworkManager command-line client, not a “BSD-style” networking subsystem
nmcli device Show device status (d is an accepted abbreviation)
nmcli device show IFACE Show interface properties
nmcli device connect IFACE Ask NetworkManager to connect the device; may activate a matching profile or create a suitable one
nmcli device disconnect IFACE Disconnect the device; can terminate remote sessions
nmcli --ask device wifi connect 'SSID' Connect to Wi-Fi, prompting for the secret when required instead of putting it in shell history or the process argument list
ss -tu TCP/UDP sockets, with selection depending on other flags
ss -tuln Listening TCP/UDP sockets, numeric addresses/ports.[89]
netstat -tuln Legacy net-tools equivalent where installed; prefer ss for routine inspection.[126]

Socket listeners are not proof of firewall reachability. Verify the intended connection from an authorized client after a change; keep the prior working profile until the new path is verified.[28][33]

rsync transfers and mirrors

Syntax is rsync [OPTIONS] SOURCE DEST; one endpoint may be remote, for example user@host:/path/. Ordinary rsync does not accept two remote endpoints in one transfer. The examples below use SSH transport.[29]

Option Meaning
-a Archive mode (-rlptgoD): recursive, links, permissions, times, group, owner, devices/special files as privileges allow; not hard links, ACLs or extended attributes
-r Recurse without implying archive metadata preservation
-v Verbose
-z Compress transfer data; benefit depends on content and link
-P --partial --progress: keep partial files and report progress; lowercase -p instead means permissions
--delete Delete extraneous destination entries within the synchronized scope; excluded/protected entries and delete timing/options matter
--exclude=PATTERN Exclude matching paths according to rsync’s filter rules
-n / --dry-run Preview without writing the transfer

A trailing slash matters: source/ copies its contents, while source includes that directory level. A partial file is not an integrity-verified backup, and -P is not a promise to resume every file from exactly the last byte. Add -H, -A, or -X only when hard links, ACLs or xattrs are required and both ends support them.[29]

Example preview for an approved test destination, with deletion deliberately absent:

rsync -anvi -e ssh -- /srv/example-source/ user@host.example:/srv/example-copy/

Before enabling a mirror’s --delete, obtain authorization for the destination, confirm both roots/trailing slashes, maintain a separate recoverable backup or protected snapshot, and inspect the itemized dry run with the exact intended filters. Do not mirror into a live database directory. Stop if the source is unexpectedly empty or unavailable. After an approved transfer, verify expected files and application-consistent recovery separately; a zero exit status alone is not a restore test.[29]

SSH identity and file copy

Protocol/tool Default port
SSH, SFTP, SCP over SSH TCP 22, unless server/client configuration selects another port.[124]

SFTP is a file-transfer protocol over SSH, not FTP with TLS. Upstream OpenSSH scp uses SFTP by default from 9.0; distribution packages can backport this change, so do not infer protocol behavior from the command name alone.[32]

Command Meaning
ssh user@host.example Open an authenticated remote session
scp FILE user@host.example:/approved/path/ Copy local to remote; quote paths as required
scp -r DIR user@host.example:/approved/path/ Recursive directory copy; validate destination and symlink behavior
scp user@host1.example:/path/FILE user@host2.example:/path/ Remote-to-remote copy; data routing/authentication behavior depends on scp options/version
ssh-keygen -t rsa -b 4096 -C 'admin@example.invalid' Create an RSA keypair if allowed by organizational policy; use an interactive passphrase and a new filename rather than overwriting an existing key
ssh-copy-id user@host.example Install an appropriate public key after authenticating the server and account; review key selection and server policy.[109]
ssh-keygen -l -f KEYFILE.pub Display a public-key fingerprint
ssh-keygen -R host.example Remove that host’s stored known-hosts trust entry; use only after the identity checks below

Keep the private key private; a passphrase protects it at rest and an agent can assist use. “Key login” is not synonymous with “no authentication.” RSA key type does not require enabling obsolete SHA-1 ssh-rsa signatures.[30][31]

A changed host key is a security event

Do not fix a warning by immediately deleting known_hosts or disabling StrictHostKeyChecking. Confirm the expected host and new fingerprint through a trusted independent channel (for example the console or an authenticated administrator/asset record). A fresh network scan alone does not establish identity.[30]

Only after confirming an authorized key rotation/rebuild: preserve the old trust record, remove the precise stale entry with ssh-keygen -R, reconnect, and compare the displayed fingerprint to the verified value before accepting. Non-default ports use the known-hosts form [host.example]:PORT; check aliases and IP entries individually. Stop and investigate if verification fails.[31]

IP addresses and reapplying configuration

Prefer NetworkManager connection profiles for persistent RHEL 9 configuration. Direct ip address changes are runtime changes and may be overwritten by the manager.[28][33]

Operation Command/reference
Inspect interface addresses ip address show dev enp1s0
Add a runtime IPv4 address ip address add 192.0.2.10/24 dev enp1s0
Remove that specific runtime address ip address del 192.0.2.10/24 dev enp1s0
Reapply supported changes to an active device nmcli device reapply enp1s0
Flush matching addresses ip address flush dev enp1s0 — disruptive; can remove both IPv4 and IPv6 selections, not a normal repair step

192.0.2.10/24 is a documentation address, not a value to assign to a production network. Do not execute add/delete/flush until the maintenance prerequisites above are met, the interface and address plan are verified, and an explicit inverse change or prior profile can be restored from the console. reapply applies only changes NetworkManager can update without full reconnection; it is not a guarantee against interruption.[28]

The older pattern dhclient -r && dhclient IFACE releases leases too broadly and can conflict with NetworkManager. On RHEL 9, do not start an independent DHCP client on a NetworkManager-managed device. Refresh/reconnect the intended profile through NetworkManager during approved maintenance instead; a profile down/up still interrupts traffic. For a genuinely unmanaged interface, use the distribution’s documented DHCP client procedure rather than this generic release-all chain.

After any approved change, inspect addresses, routes and DNS, test the gateway and intended service from the correct network, and verify a new management connection before closing the console. If it fails, restore the recorded profile/addresses from that console—not by stacking further speculative changes.
