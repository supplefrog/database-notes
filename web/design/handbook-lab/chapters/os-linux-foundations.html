Linux

The administration examples in these OS chapters use RHEL 9 on x86-64, Bash, systemd, GNU tools and NetworkManager, unless a section explicitly names an alternative. Distribution packages carry backports: use the installed man page and --version output when checking an option, not an assumed upstream “latest” version. Windows instructions, when present, are labeled separately.[120]

Distributions

A distribution combines a Linux kernel, userspace tools, libraries, packages and integration policy. Individuals, communities or companies maintain distributions. Package managers differ: RHEL 9 uses DNF/RPM; Debian-family systems commonly use APT/dpkg. Prefer the distribution’s configured, trusted repositories over arbitrary downloaded binaries, and review a package transaction before applying it.[50][8]

Kernel

Linux is a Unix-like kernel initially developed by Linus Torvalds, with ongoing work by many contributors. It is predominantly written in C with architecture-specific code; upstream also supports Rust for selected kernel development. That does not mean every RHEL 9 kernel or driver is Rust-enabled.[15][95]

Linux predates Git: the Git project dates its creation for Linux development to 2005.[138] Kernel development uses Git today; kernel.org hosts project infrastructure and repositories, and torvalds/linux is also available on GitHub.[15][45] Hosting a mirror is different from making that forge’s issue/pull-request workflow the kernel’s contribution process.[96]

Terminal emulators

A terminal emulator displays text and connects input/output to a command-line program. GNOME Terminal and st are examples. A terminal can host Bash, another shell or a non-shell program.

Shells and startup files

A shell is a userspace command interpreter. Interactive versus noninteractive and login versus non-login are separate properties. /sbin/nologin is a program used to refuse login, not an example of a normal noninteractive command-processing shell.[114]

For Bash invoked as Bash (not its separate sh compatibility mode):[17]

Invocation Typical startup behavior
Interactive login shell, or Bash invoked with --login Reads /etc/profile, then the first readable file among ~/.bash_profile, ~/.bash_login, ~/.profile
Interactive non-login shell Reads ~/.bashrc; distribution defaults can add global setup through that file
Noninteractive shell Normally reads the file named by BASH_ENV, if set; --login changes startup behavior

A non-login shell does not inherently lack the user’s environment: it inherits exported variables from its parent and may read user configuration. A typical Bash profile explicitly sources ~/.bashrc. Remote invocation and special modes have additional rules; inspect actual startup files before diagnosing a PATH difference.[17]

GNU utilities

GNU supplies free-software Unix-like userspace tools such as coreutils and Bash. A Linux system combines software from many projects; systemd, OpenSSH and the Linux kernel are not all “GNU utilities.” GNU option syntax may differ from BSD/macOS tools.[19][18]
