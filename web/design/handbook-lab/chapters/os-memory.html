Memory management

Pages and segments

Pages divide virtual memory into fixed-size units; physical page frames provide RAM backing. Page size is architecture-dependent, and larger page sizes may also be supported. Page tables describe mappings and access attributes.[1]

Segments are variable-size logical regions in the classic segmentation model, such as code, data and stack. Do not confuse a program’s logical regions with the fixed-size pages backing them; modern Linux virtual memory is primarily described through mappings and pages.[86][1]

Virtual memory

Virtual memory gives programs virtual addresses that the CPU and kernel map to physical memory or other backing. It supports separate address spaces, controlled sharing, protection, demand allocation and file mappings. It works even when no swap is configured.[1]

  • A page fault can demand allocation or loading of a valid page; an invalid access can instead fault the process.
  • File-backed pages may be read from a file; clean cached pages can be discarded and read again.
  • Eligible anonymous pages may be written to swap and brought back later. Swap is backing storage, not extra RAM with RAM’s latency.
  • Reclaim and compaction respond to memory pressure. If memory cannot be made available, an allocation may fail or the out-of-memory mechanism may select a task to kill.[1]

Use memory and I/O statistics to investigate pressure; do not infer a memory leak merely from low “free” RAM, because caches also consume RAM.
