Interactive client workflow

In the mysql interactive client, these are client commands, not SQL sent through a connector:

prompt (\u@\h) [\d]>\_
tee /secure/operator/mysql-session.log
SELECT NOW();
SELECT DATABASE();
notee

\u, \h and \d expand user, host and current database; \_ is a space. tee appends statements/output to the named local file. Create a private directory and restrict file access before using it; account changes, query results and personal data can leak into transcripts. notee, not NOTEEE, stops logging. Do not use session logging during secret-entry/recovery operations.

Move an existing data directory

EL9 RPM service; planned outage. Have a tested backup, a rollback window, console access and capacity for both old and new copies. A raw filesystem copy while MySQL is writing is not a consistent backup. External tablespaces, keyring data, log files and certificates may live outside @@datadir; inventory them separately.

  1. Record the active datadir, all related file paths, server UUID/version, option files, ownership/ACLs/extended attributes, SELinux contexts, service restrictions and mount dependencies. Select an empty destination, for example /srv/mysql-data, not a directory already containing another instance.
  2. Stop the exact instance through systemd; verify no process is using its datadir and that shutdown completed. Prevent accidental restart during copying. Do not kill unrelated clients or servers.
  3. Copy contents of /var/lib/mysql/ into /srv/mysql-data/, preserving numeric owners, modes, links, ACLs and xattrs. On EL9 a suitable tool is rsync -aHAX --numeric-ids /var/lib/mysql/ /srv/mysql-data/ while stopped. The trailing slash is intentional; cp -r /var/lib/mysql /newpath may instead create /newpath/mysql and lose required metadata.
  4. Verify the copied file set/metadata and offline checksums while both remain unchanged. Do not recursively make every file executable with chmod -R 750; use directory and file permissions appropriate to their existing roles, with private keys restricted.
  5. Change the intended datadir option and any deliberately moved socket/log/PID paths. Update only needed client settings, SELinux exact-path contexts, mount/service access and backup tooling. Apply persistent file-context mappings and restore labels, not just temporary chcon changes.
  6. Validate configuration, start the intended instance, inspect error logs and verify @@datadir, expected schemas/data, encryption/key access, application behavior and replication/backup jobs. Do not allow the first start to initialize a mistakenly empty/unmounted target.
  7. Keep the original stopped copy until verification and rollback retention complete. If rolling back before accepting new writes, stop the new instance, restore old path/config/policy and start the old copy. After new writes, switching back loses them: reconcile/recover them under a planned rollback, not a blind path reversal.

Do not delete the old datadir as part of the first successful startup.
