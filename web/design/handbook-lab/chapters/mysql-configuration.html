Applies to MySQL Server 8.4 LTS; the production baseline is RHEL 9 x86_64 with Oracle MySQL Community RPMs from the MySQL Yum repository. Separately licensed products and other platforms are identified explicitly.[1][72]

Option files

Review the complete configuration appendix before adapting settings. On the selected RPM platform /etc/my.cnf is a normal option-file location; included files, command-line options and mysqld-auto.cnf can also affect effective settings. mysqld --verbose --help reports option-file search locations and recognized options. Use mysqld --validate-config with the intended configuration before a maintenance restart; it is not a storage/permissions/replication health test.

Keep a restricted backup of the effective option files. Edit a reviewed local copy, preserve ownership/mode, inspect a diff, and deploy deliberately. Do not download a blog file straight into /etc.

Vendor systemd units and overrides

Use the installed RPM’s mysqld.service. Read it and its overrides first:

systemctl cat mysqld.service
systemctl show mysqld.service -p FragmentPath -p DropInPaths -p User -p Group

Prefer a narrow systemctl edit mysqld.service drop-in over replacing the vendor unit in /usr/lib/systemd/system. A complete unit in /etc/systemd/system shadows vendor updates and makes you responsible for maintaining the entire unit. systemctl daemon-reload reloads unit definitions, not MySQL option files; a server restart is separately planned.

The single-instance unit appendix explains the source unit’s invalid EnvironmentFile assignment and package-specific pre-start helper. The multiple-instance template explains %I, suffix groups and unique paths. Generic tarball installations need their own tested service integration; they cannot assume RPM helper paths.

Relocate an existing RHEL RPM instance without reinitializing it

This is a same-host, same-version cold move of the existing default instance from /var/lib/mysql to an approved empty /srv/mysql-data, not a clone, upgrade or live rsync backup. Keep the original directory unchanged for rollback. A separate new instance has different UUID/identity requirements. Rehearse this move and restore the backup before the production window.

  1. Record effective datadir, socket, PID, error/binlog/relay/undo/tablespace/keyring paths and server_uuid; locate external files and absolute paths in configuration/log index files. A directory copy does not relocate every dependency. If external tablespaces or absolute log paths are present, retain accessible paths or follow their documented move procedure; do not edit managed data files speculatively. Back up data, keys, config, unit overrides, SELinux customizations and client/backup connection settings.
  2. Quiesce writers and scheduled jobs, stop the exact unit with sudo systemctl stop mysqld.service, and confirm it is inactive and no process still owns the datadir. Confirm clean shutdown in the error log. Never copy changing InnoDB files and call that a cold backup.
  3. Provision and verify the intended destination filesystem/mount, free space, ACL/xattr support and ownership. The destination must be empty intentionally, not an absent mount. For approved directories, inspect the dry run, then copy the stopped tree:
sudo rsync -aHAXn --numeric-ids /var/lib/mysql/ /srv/mysql-data/
# Only after reviewing the dry run and confirming the server is stopped:
sudo rsync -aHAX --numeric-ids /var/lib/mysql/ /srv/mysql-data/
sudo rsync -aHAXnrc --numeric-ids /var/lib/mysql/ /srv/mysql-data/

Check every exit status and investigate any content difference in the checksum comparison; no --delete is used. This preserves metadata where the destination supports it, but copied SELinux xattrs must then be reconciled with the new persistent path policy.

  1. With policycoreutils-python-utils installed, inspect semanage fcontext -l -C and matchpathcon first. If no conflicting local mapping exists, use an equivalence mapping so the relocated tree inherits the standard datadir’s differentiated socket/file rules, rather than assigning one type to every file:
sudo semanage fcontext -a -e /var/lib/mysql /srv/mysql-data
sudo restorecon -Rv /srv/mysql-data
ls -ldZ /srv/mysql-data

Existing mappings require reviewed modification, not another blind -a. Verify database files use mysqld_db_t and the configured socket/PID use mysqld_var_run_t; error logs use mysqld_log_t. Keep the standard /var/log/mysqld.log in this move. A custom log or runtime directory needs its own mapping and permissions, not the data-directory type.

  1. Change the intended option group to datadir=/srv/mysql-data and socket=/srv/mysql-data/mysql.sock; update the intended clients/backup/monitoring socket settings. Preserve auto.cnf for this same instance. Keep PID/error-log locations unchanged unless separately planned. In /etc/sysconfig/mysql, preserve other values and set NO_INIT=true for the initialized instance, reviewing its effect on other units. Add a narrow systemctl edit mysqld.service drop-in:
[Unit]
RequiresMountsFor=/srv/mysql-data

This orders/requires the mounts necessary to access the path; it does not prove the correct volume or database is present. Confirm the expected volume and retained data explicitly. Reload systemd definitions, validate server configuration, and start the intended unit. Do not start a second service over the old directory while validating the new one.

  1. Inspect the unit journal/MySQL log, getenforce, ls -lZ for newly created socket/PID, and relevant AVCs. Connect explicitly to the new socket and check @@datadir, @@socket, @@server_uuid, object/data invariants and replication state. Test application traffic, a fresh backup/restore and boot/mount failure behavior before retiring the old path.
  2. On failure before new writes, stop the new-path unit, restore prior option files/drop-in/socket clients and the previous environment setting, then restart only the unchanged old instance. Remove only the SELinux mapping introduced by this change if abandoning the destination. If new writes were accepted, the old directory is stale: reconcile/restore current data before reverting. Never reverse-copy a live tree or leave two active writers as rollback.

A configuration is a workload decision

Target: Oracle MySQL 8.4 LTS RPMs on RHEL 9 x86-64. Start from the package’s installed configuration, not an old blog download. The historical file below is retained in full for comparison, not deployment.

Minimal local-only starting fragment

For a deliberately new single instance with the RPM’s standard datadir/socket/error-log locations, this fragment documents the identity/path choices. It is not a complete production performance, replication or encryption configuration:

[mysqld]
user=mysql
datadir=/var/lib/mysql
socket=/var/lib/mysql/mysql.sock
log-error=/var/log/mysqld.log
bind_address=127.0.0.1

[client]
socket=/var/lib/mysql/mysql.sock

A TCP loopback bind does not configure every additional listener (for example X Protocol); inventory those separately. Add the narrow approved bind address, firewall and TLS requirements before remote use. Verify mounts and existing data before starting; an empty wrong path can be initialized as a new instance by package helpers.

Every source option, interpreted for 8.4

Source option/group Review and replacement guidance
innodb_buffer_pool_size=5600M; 70%/10% comments Not a portable default. Measure memory limits/working set, connection buffers, other services and OS headroom; 128 MiB is the ordinary small default unless other sizing automation changes it.
disable_log_bin Disables binary logging and breaks ordinary binlog replication/PITR. Only choose deliberately for a role that does not need it; never a routine performance fix.
binlog_expire_logs_seconds=604800 Seven-day example, not a safe universal retention window. Keep all logs required by backups, delayed/disconnected replicas and recovery policy. Historical expire_logs_days is not the 8.4 configuration to revive.
binlog_encryption=ON Requires supported initialized key management; verify binlog/relay-log encryption, key backups and remote recovery access. Does not encrypt every database/log file.
binlog_do_db=test Source-side filtering can omit required changes with format-dependent semantics. Avoid casual filtering on a source used for full recovery.
slow_query_log, slow_query_log_file, long_query_time=10 Enable with explicit file/output, threshold and retention; ten seconds is an example/default, not a tuning recommendation.
general_log, general_log_file=general.index General logging can capture secrets/PII and add load. The .index suffix does not make it a binary-log index. Use descriptive paths and restrict access.
join_buffer_size=128M, sort_buffer_size=2M, read_rnd_buffer_size=2M Connection/operation memory can multiply across concurrency. Do not allocate globally on a “reporting servers are different” slogan; measure queries and session-scope changes where appropriate.
default-authentication-plugin=mysql_native_password Removed default_authentication_plugin configuration is invalid in 8.4. mysql_native_password is disabled by default; upgrade clients for caching_sha2_password and TLS rather than weakening auth globally.
plugin_load_add=group_replication.so, mysql_clone.so Distinct optional plugins; clone has overwrite/compatibility prerequisites.
group_replication_communication_stack, group UUID, local address, seeds Must match a designed compatible topology and secure communication; copied UUIDs/two-host examples do not establish quorum or HA.
Single-/multi-primary settings Do not switch off single-primary or enable update-everywhere checks without reviewing Group Replication restrictions and application conflict handling.
server_id Unique nonzero replication identity; not enough by itself because server UUIDs must be unique too.
gtid_mode=ON, enforce_gtid_consistency=ON Suitable planned new-topology settings; existing OFF topologies require the coordinated transition sequence.
port=3307, multiple bind_address values Resolve listener conflicts, supported syntax, firewall/SELinux and client routing. Neither setting assigns resource isolation or secures all listeners.
datadir, socket, log-error, pid-file Paths must match service layout/permissions/labels and be unique per instance. /var/run is commonly /run; runtime directories must be created by the appropriate service/package mechanism.
lc_messages_dir Must refer to message files from the selected distribution; tarball paths do not necessarily match RPM layout.
log_timestamps=SYSTEM Chooses local time for supported logs; UTC is often easier for distributed correlation. Record timezone/DST assumptions if using SYSTEM.
user=mysql OS process identity, not a SQL user; use the installed service account.
[mysqld1] Used by explicit suffix 1; RPM template units use groups like [mysqld@replica01] instead.
[mysql] socket mysql client-specific default; [client] applies to supported client programs. Socket values do not automatically select every named instance.

Back up current option files, review precedence/includes/persisted settings, validate syntax with the chosen server binary, restart only in the planned window and verify effective variables/listeners/logs. To roll back, restore the reviewed prior settings; do not assume deleting an option undoes a persisted value.

mysqld.service

Historical source example for reading, not a tested procedure or executable download.

Applies to MySQL Server 8.4 LTS; the production baseline is RHEL 9 x86_64 with Oracle MySQL Community RPMs from the MySQL Yum repository. Separately licensed products and other platforms are identified explicitly.[1][72]

Prefer the vendor unit

Target: RHEL 9 x86-64 Oracle MySQL 8.4 RPM installation. Read systemctl cat mysqld.service and existing drop-ins. Use the installed package’s unit, not the historical complete replacement below. Generic archives may lack its paths, helper and systemd-notification support.

Correct the concrete unit defects

Source directive Meaning / decision
Copyright/header Oracle copyright is retained verbatim. The prose says “forking” but Type=notify describes a notifying service, not Type=forking.
After / Wants=network-online.target Ordering and weak dependency; they do not prove DNS/remote storage/application readiness.
After=syslog.target Historical ordering choice; retain the vendor’s tested dependencies rather than assuming this controls modern journald.
WantedBy=multi-user.target Installation enablement target; enable is distinct from start.
User=mysql, Group=mysql Service OS identity; filesystem/policy access must permit all configured paths.
Type=notify Works only when the installed server supports and sends readiness notification. Do not silently replace with forking to hide a timeout.
TimeoutSec=0 Disables timeout; inherited package behavior is not an argument to remove all operational startup monitoring.
PermissionsStartOnly=true Legacy/deprecated systemd control that exempts pre/post commands from some identity settings. Do not copy it into new units as a current best practice; package/version semantics matter.
ExecStartPre=/usr/bin/mysqld_pre_systemd RPM helper, not universally shipped. Can initialize an empty datadir; verify required mounts/data before start.
ExecStart=/usr/sbin/mysqld $MYSQLD_OPTS Path and option ordering must match package/server behavior. Do not replace with a tarball path without reviewing the entire unit.
EnvironmentFile="MYSQLD_OPTS=--defaults-file=/etc/my.cnf" Invalid use: EnvironmentFile takes file paths, not an assignment. Use an actual environment-file path or Environment="MYSQLD_OPTS=..." in a reviewed override. /etc/my.cnf is already a normal RPM option-file location.
EnvironmentFile=-/etc/sysconfig/mysql Reads optional assignments from that file; leading - allows missing file. This is not the same as [mysqld] syntax.
LimitNOFILE=10000 OS descriptor limit, not a universal workload tuning value; compare effective systemd/server limits.
Restart=on-failure, RestartPreventExitStatus=1 Restart policy; repeated failure needs diagnosis, not an endless reset/restart loop.
Environment=MYSQLD_PARENT_PID=1 Package integration setting used for restart behavior; not a generic daemonization technique.
PrivateTmp=false Does not isolate the service’s temporary namespace. Change hardening options only after verifying file/path and server-feature requirements.

A narrow drop-in, not a replacement unit

For a validated workload that needs a chosen descriptor ceiling, use systemctl edit mysqld.service and a reviewed fragment such as:

[Service]
LimitNOFILE=10000

The number is an example decision to verify, not a performance promise. After a unit change, systemctl daemon-reload; schedule a controlled restart, inspect status/error logs and systemctl show mysqld.service -p LimitNOFILE, and verify SQL-level effective limits. mysqld --validate-config does not validate a systemd unit. A unit can also be checked with the installed systemd-analyze verify using the actual unit path, without claiming that static checks prove startup.

Rollback only the drop-in you added and reload definitions; do not delete unrelated overrides. Preserve the prior datadir/configuration and verify normal restart.
