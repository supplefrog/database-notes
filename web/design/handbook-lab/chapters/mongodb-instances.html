Diagnose the first failing boundary

Read-only first. A successful TCP connection proves neither authentication nor replica-set readiness.[6][104]

sudo systemctl status mongod --no-pager
sudo systemctl cat mongod
sudo journalctl -u mongod -n 100 --no-pager
sudo ss -ltnp
sudo stat /etc/mongod.conf /var/lib/mongo /var/log/mongodb
sudo -u mongod test -w /var/lib/mongo
sudo -u mongod test -w /var/log/mongodb

Inspect /var/log/mongodb/mongod.log as well as the journal. Redact client data, tokens and infrastructure details before sharing logs.

Symptom Check Safe next action
Unit not found Correct official package; unit search paths systemctl daemon-reload after installing/changing a unit, not after merely editing YAML
YAML/unknown-option error Spaces, hierarchy, exact 8.0 option Restore prior config; never solve by deleting all security settings
Address already in use Listener/process on chosen port Correct instance port; do not kill an unidentified process
Permission denied Service user, every parent directory, log/cert/key permissions Fix only intended owner/path; avoid recursive world-writable permissions
DBPathInUse / lock failure Another process using same path Identify owner; do not remove lock files while a server may be alive
TLS handshake failure CA chain, SAN hostname, expiry, clocks, client certificate policy Repair trust/identity; never tlsAllowInvalidCertificates as the fix
Authentication failure Username, authSource, mechanism, expired/rotated credentials Test a fresh authenticated session; distinguish Unauthorized from bad credentials
No primary / selection timeout Member DNS, ports, majority, rs.status() Repair topology/network; direct connection is diagnostic, not an HA fix
Disk full / OOM Free space, log growth, cache/resource budget Add capacity or reduce pressure; do not remove WiredTiger/journal files

On RHEL 9 check both DAC and SELinux: ownership alone cannot fix a label/domain denial. Use getenforce, ls -ldZ, matchpathcon -V, ps -eZ and sudo ausearch -m AVC,USER_AVC -ts recent. Check auditd if audit results are empty. Repair known labeling/configuration problems first; never use permissive mode or blindly install audit2allow output. bindIp selects local interfaces, not a client allowlist; apply scoped firewalld access.[110]

Integrate custom paths, ports and units

A second process or relocated dbPath is outside the standard RPM policy assumptions. Prefer a separate restore host with the ordinary package layout when you do not have an approved custom integration. The following persistent label mappings are inputs to that integration, not a claim that relabeling alone provides a complete custom policy. Have the SELinux owner inspect the loaded policy, domain transition, parent-directory traversal, runtime and secret access; rehearse startup, shutdown, log rotation and recovery under enforcing mode before authorizing use.[103][104][110]

For the same-trust restore instance below, the base MongoDB policy defines these types. Check existing local rules (semanage fcontext -l -C) before adding; if an exact rule exists, inspect it and deliberately modify that rule rather than applying duplicate mappings or overwriting unrelated labels.[107][108]

sudo semanage fcontext -l -C
sudo semanage fcontext -a -t mongod_var_lib_t '/srv/mongodb/restore(/.*)?'
sudo semanage fcontext -a -t mongod_runtime_t '/run/mongodb-restore(/.*)?'
sudo semanage fcontext -a -t mongod_unit_file_t '/etc/systemd/system/mongod-restore\.service'
sudo restorecon -Rv /srv/mongodb/restore
# Run after saving the unit/config; /run directory is created by systemd.
sudo restorecon -v /etc/systemd/system/mongod-restore.service /etc/mongod-restore.conf
sudo semanage port -l | grep '^mongod_port_t'

The pinned policy names runtime type mongod_runtime_t with mongod_var_run_t as an alias. Data needs mongod_var_lib_t; logs need mongod_log_t. The existing /var/log/mongodb(/.*)? mapping includes restore.log. A new log directory needs its own persistent semanage fcontext -a -t mongod_log_t '/chosen/log(/.*)?' and restorecon -Rv /chosen/log, plus ownership and traversable parents. Do not use one transient chcon as a persistent solution.[107][108][110]

The base RHEL port type normally already includes TCP 27017–27019. Inspect before adding: the restore port 27018 and shard/config ports 27018/27019 must not be blindly re-added. For a genuinely unassigned custom port, after policy review use, for example, sudo semanage port -a -t mongod_port_t -p tcp 28020. If another service owns the port label, stop and choose/review the conflict; do not steal it with -m. Change YAML, client/member endpoints, firewall and monitoring together. Port labeling is not a firewall rule.[103][105][110]

After starting the reviewed service, require mongod_t, the intended runtime/path labels, no unexplained AVC denials, correct effective settings and authenticated allowed/denied operations. sudo -u mongod test -r FILE tests DAC, not the daemon’s SELinux domain. Unconfined execution is not success. A failed custom policy gate means stop the instance and repair/escalate; do not make the whole host permissive.[108][110]

For relocated data on a separate mount, add a root-owned drop-in /etc/systemd/system/mongod.service.d/storage.conf:

[Unit]
RequiresMountsFor=/srv/mongodb/main

Configure and verify the mount itself in the platform’s persistent mount configuration. RequiresMountsFor orders/requires known mount units; it does not invent a mount or prove the expected volume is mounted. Check findmnt --target /srv/mongodb/main, filesystem UUID/source/options, ownership and labels before copying and after a controlled reboot. Do not allow startup on an empty underlying root-filesystem directory if a required volume is missing. For extra safety use an approved ConditionPathIsMountPoint on the actual mountpoint when appropriate. Reload systemd after unit/drop-in edits, not for a YAML-only change.

Separate instance identity and resources

Use another standalone instance for a disposable exercise or restore; do not call two processes on one disk “HA.” Independent paths and users do not reserve CPU/RAM/I/O. Set a combined memory budget and use service/cgroup limits only after observing startup and workload behavior.[6][10]

Property Main package instance Disposable restore instance
Service mongod mongod-restore
Config /etc/mongod.conf /etc/mongod-restore.conf
dbPath /var/lib/mongo /srv/mongodb/restore
Log /var/log/mongodb/mongod.log /var/log/mongodb/restore.log
TCP 27017 27018
Bind Loopback until hardened Loopback only
OS account mongod mongod in this disposable same-trust example; use separate account for security separation

Create a new empty target directory. Never copy a running dbPath into it. On a fresh host create the path first, then apply the persistent mappings above after saving its unit/config; the order matters because restorecon cannot label an absent path.[21][110]

sudo install -d -o mongod -g mongod -m 700 /srv/mongodb/restore

/etc/mongod-restore.conf:

storage:
  dbPath: /srv/mongodb/restore
  wiredTiger:
    engineConfig:
      cacheSizeGB: 0.5
systemLog:
  destination: file
  path: /var/log/mongodb/restore.log
  logAppend: true
net:
  port: 27018
  bindIp: 127.0.0.1
  unixDomainSocket:
    enabled: false
security:
  authorization: enabled

The 0.5 GB cache is an explicit small-lab allocation, not a production recommendation or a total memory cap. This same-trust custom unit preserves the RPM foreground/glibc/limit contract; it is not supplied or automatically confined by the RPM. Complete the custom integration gate before starting.[101][103] /etc/systemd/system/mongod-restore.service:[6][10]

[Unit]
Description=MongoDB isolated restore instance
After=network-online.target
Wants=network-online.target
RequiresMountsFor=/srv/mongodb/restore

[Service]
Type=simple
User=mongod
Group=mongod
Environment="MONGODB_CONFIG_OVERRIDE_NOFORK=1"
Environment="GLIBC_TUNABLES=glibc.pthread.rseq=0"
RuntimeDirectory=mongodb-restore
RuntimeDirectoryMode=0750
ExecStart=/usr/bin/mongod --config /etc/mongod-restore.conf
Restart=no
LimitNOFILE=64000
LimitNPROC=64000
LimitMEMLOCK=infinity
LimitFSIZE=infinity
LimitCPU=infinity
LimitAS=infinity
TasksMax=infinity
TimeoutStopSec=infinity

[Install]
WantedBy=multi-user.target

sudo chown root:mongod /etc/mongod-restore.conf
sudo chmod 640 /etc/mongod-restore.conf
sudo restorecon -v /etc/mongod-restore.conf /etc/systemd/system/mongod-restore.service
sudo systemd-analyze verify /etc/systemd/system/mongod-restore.service
sudo systemctl daemon-reload
# Start only after the custom SELinux/mount checks below are accepted.
sudo systemctl start mongod-restore
sudo systemctl status mongod-restore --no-pager
mongosh --host 127.0.0.1 --port 27018

Run the first-user bootstrap at 27018, creating destination-specific credentials. Do not assume main-instance users exist here. Check getCmdLineOpts, protected access and paths at 27018 before restoring. Do not enable restore-instance boot start; stop it after the drill. Keep authentication enabled even on this isolated instance because other local users may connect.[7][9]

Relocate a standalone safely

Disruptive; physical data copy. This procedure moves one standalone, not a sharded cluster and not a replica-set failover. Have a restorable backup, destination capacity, maintenance window and a recorded old config. Keep the old directory intact until acceptance.[6][21]

  1. Quiesce application writes; stop the exact service cleanly. Confirm it stopped and no process uses the old dbPath.
  2. Create an empty destination on supported local storage; copy the whole stopped directory, preserving ownership/modes. This example uses /srv/mongodb/main and assumes it did not previously exist.
  3. Change only storage.dbPath, plus any required confinement/mount policy. Verify persistent mount availability before boot start.
  4. Start and inspect recovery logs, effective path, users, collections/indexes and application read/write checks.
sudo systemctl stop mongod
sudo systemctl is-active mongod
sudo install -d -o mongod -g mongod -m 700 /srv/mongodb/main
sudo cp -a /var/lib/mongo/. /srv/mongodb/main/
# STOP on copy error; confirm size/file inventory and intended ownership.
sudo semanage fcontext -a -t mongod_var_lib_t '/srv/mongodb/main(/.*)?'
sudo restorecon -Rv /srv/mongodb/main
# Edit /etc/mongod.conf: storage.dbPath: /srv/mongodb/main
# Add the mount dependency/drop-in described below; complete policy review.
sudo systemctl daemon-reload
sudo systemctl start mongod

Inspect the source mount using findmnt --target /var/lib/mongo and target mount using findmnt --target /srv/mongodb/main before the copy. The fcontext addition in this example assumes no existing exact local mapping; use the conflict checks above. An inactive result is expected after stop, but confirm process termination separately before copying. Copy failure means do not start from the partial target. If validation fails before new writes, stop, restore the old path/config and restart. Once new writes have landed at the new location, reverting paths loses them; stop traffic and reconcile/restore instead. Never run both directory copies as competing authoritative servers.[21]

Stop and rotate deliberately

systemctl stop mongod requests orderly shutdown; kill -9 is not normal administration. Inspect systemctl show mongod -p TimeoutStopUSec -p SendSIGKILL: the vendor unit does not specify its own stop timeout, so systemd defaults/drop-ins matter. For shutdowns that need more time, use an approved service drop-in (for example TimeoutStopSec=infinity under [Service]) and a supervised escalation plan; do not assume the default timeout cannot end in SIGKILL.[101] On a replica set, use a secondary-first maintenance plan rather than stopping the primary casually. systemctl restart disconnects clients; driver retry behavior does not make it invisible.[27][104]

Default file-log rotation by MongoDB renames the old file and opens a new one. Run as an identity with logRotate privilege (clusterAdmin includes cluster-management capabilities):[43][85]

db.getSiblingDB("admin").runCommand({logRotate: 1});

Check the new log receives entries, then compress/archive only the closed old file under retention policy. If integrating OS logrotate with systemLog.logRotate: reopen, also set logAppend: true, rename externally, and issue logRotate; do not mix the two rotation modes or truncate a live log blindly. Logs may contain query data and need restrictive access, rotation and off-host retention appropriate to policy.[43]
