Applies to MySQL Server 8.4 LTS; the production baseline is RHEL 9 x86_64 with Oracle MySQL Community RPMs from the MySQL Yum repository. Separately licensed products and other platforms are identified explicitly.[1][72]

Scope and compatibility gate

Source target: MySQL 8.4 LTS. Migration-workflow reference: Oracle SQL Developer 24.3, targeting an independently patched/supported Oracle Database 19c installation with the chosen PDB/service, character set and licensing approved by its DBA. This is a migration to Oracle, not PostgreSQL or MongoDB.

The 24.3 migration guide still names old Connector/J releases in its MySQL preparation section. That is not evidence that those drivers support MySQL 8.4 authentication/TLS, nor proof of a certified end-to-end 8.4 migration path. Before using the wizard, validate the exact SQL Developer/JDK/Connector-J/server tuple against vendor compatibility guidance and a representative disposable rehearsal. If that tuple is not supported/working, choose a supported export/transform/load path with equivalent validation; do not downgrade authentication or install an obsolete driver just to match an old screenshot.

Prepare and connect

  1. Back up both systems and rehearse recovery. Inventory schemas, row counts, keys, types/collations, routines/triggers/events, views, definers, privileges, dependencies and application SQL. Establish outage/CDC requirements and an agreed reconciliation plan.
  2. Obtain a Connector/J release compatible with the actual MySQL 8.4/JDK/security requirements from Oracle’s official Connector/J distribution. Check its license and support terms. In SQL Developer, add its JAR through Tools → Preferences → Database → Third Party JDBC Drivers and restart if required. Do not mix unrelated drivers in the same classpath.
  3. Create/test the MySQL source connection with metadata/data access needed for capture, not a root account. Verify TLS identity and character/timezone handling. An account that cannot see routine definitions cannot migrate them merely because it can execute the routine.
  4. Create/test the Oracle connection to the intended PDB/service, not accidentally the root container or SYSTEM schema. Keep repository, deployment operator and application-owner responsibilities separate.

Migration repository and least privilege

The repository is an Oracle schema storing captured and converted models. The wizard repository connection must be Oracle, not the MySQL source. SQL Developer manages repository association; if no repository exists, create/provision and associate one before the wizard. Right-click the Oracle repository connection → Migration Repository → Associate Migration Repository.

Do not reuse the old GRANT ... IDENTIFIED BY account-creation syntax or grant unlimited quota on SYSTEM. Oracle 19c creates an account with CREATE USER, then grants authorized privileges separately. Use a dedicated approved non-SYSTEM permanent tablespace, appropriate temporary tablespace and bounded quota sized for the captured metadata/data needs. A DBA supplies the credential securely; no literal password is included here.

Identity Minimum-scope decision
MySQL capture account Read only the chosen schemas/metadata, including routine/view definitions as needed; no blanket replication/admin privileges merely for capture.
Oracle repository owner The SQL Developer guide specifies RESOURCE plus CREATE SESSION, CREATE VIEW and CREATE MATERIALIZED VIEW for its repository, with extra admin privileges for multischema workflows. Review what RESOURCE grants on the actual 19c installation; do not infer a universally minimal custom grant list from its name. Grant only the documented features used, with bounded tablespace quota.
Oracle DDL deployment operator Generated cross-schema DDL can require powerful ANY/admin privileges listed by SQL Developer. Do not grant this entire set to the persistent repository/application account by default. Have a DBA review/split the generated script and deploy under controlled temporary authority or schema-owner sessions where possible; audit and revoke temporary grants afterward.
Oracle application owner/runtime Own only intended target objects; runtime account receives only needed object privileges, not RESOURCE/DBA or ANY privileges as a shortcut.

The official migration guide’s broad deployment privilege list is a tooling requirement for certain automated cross-schema operations, not a least-privilege production role. If unattended wizard deployment cannot fit the site’s authorization model, export the generated DDL and use the reviewed deployment path instead. Never migrate as SYS. Keep the repository after cutover only as long as needed and protect it as sensitive metadata.

Capture, convert, review, load

Open Tools → Migration → Migrate after compatibility and accounts are validated.

Wizard stage What to supply/check
Repository The Oracle repository connection. Do not select MySQL here; review any truncate/clear-existing-project choice because it deletes repository history.
Project Explicit project name/output directory; protect generated scripts and avoid overwriting another migration.
Source database Online MySQL connection, or a supported offline capture path. Capture privileges determine what is visible.
Capture Select the exact databases/objects; compare captured inventory to the source. Missing definitions are not successful exclusions.
Convert Review every mapping and conversion warning. Do not accept defaults without evaluating semantics.
Target database Intended Oracle PDB/service/schema and reviewed DDL deployment identity. Inspect generated CREATE/ALTER/DROP statements before execution.
Move data Choose online transfer for an appropriate bounded workload or supported offline unload/load. Ensure source consistency and define the cutover/delta boundary.
Summary Review logs, rejected records, object failures and incomplete conversions; “Finish” is not acceptance.

Conversion details to test

MySQL feature/data Oracle review
TINYINT, INT, unsigned ranges Often map to NUMBER with chosen precision/scale; preserve full signed/unsigned range and application boolean conventions, not just the type name.
AUTO_INCREMENT Review identity/sequence generation and next-value synchronization, including explicit existing IDs and concurrent writers.
Character data/collation Character sets, case/accent comparison, length semantics and index limits can change query/uniqueness behavior.
Empty strings and NULL Oracle character semantics differ; test sentinel values and constraints explicitly.
Dates/timestamps Check zero/invalid dates, range, fractional seconds, timezone conversion and defaults.
JSON, ENUM/SET, binary/LOBs Choose a supported 19c representation and transformations; do not assume a textual CAST preserves semantics or indexes.
Routines, triggers, events MySQL procedural SQL is not PL/SQL; manually review transactional behavior, exceptions, delimiters, definers and scheduling equivalents.
Indexes/defaults/constraints Names and syntax can change; preserve meaning and dependencies. Test foreign keys, unique constraints and generated/default expressions.

Validate, cut over and roll back

Compare object inventories and normalized definitions; compare row counts plus keyed checksums/samples and business invariants; investigate rejected/truncated rows. Test application SQL, transactions, locking, error handling, performance and all background jobs. Rename indexes or set defaults only through reviewed DDL, not ad hoc cleanup hiding conversion errors.

Freeze or capture final source writes under the approved migration strategy; validate the final delta boundary, switch applications and monitor. Keep the old source recoverable/read-only for the planned rollback window. Once Oracle accepts writes, a reverse cutover needs reconciliation or a defined loss window; pointing applications back to the old MySQL copy is not automatically safe.

Offline alternative

mysqldump emits MySQL SQL, not Oracle SQL or SQL*Loader control files. Do not pipe it into SQLPlus/SQLLoader. Use the supported SQL Developer unload/load scripts or a reviewed data export format with explicit encoding, escaping, NULL representation, date/LOB handling, Oracle DDL and SQL*Loader/external-table configuration. Test each transformation and account for rejects. Third-party/CDC tools and Oracle features have separate compatibility/licensing requirements; no universal “dump → convert → import” executable recipe is claimed.
