Install PostgreSQL 18 on RHEL 9

Use a new authorized RHEL 9.7 x86_64 host, systemd, SELinux Enforcing, persistent storage and working DNS/time. The selected upstream PGDG RPM build is PostgreSQL 18.6-1PGDG.rhel9.7, not Red Hat’s AppStream PostgreSQL. PGDG supports the last two RHEL minors and publishes minor-specific repositories because OpenSSL changes broke cross-minor dependencies. The inspected 9.7 repository contains this build; recheck the maintained-minor matrix before every installation/update. A RHEL EUS entitlement does not extend PGDG’s package-support window. If 9.7 is no longer maintained, stop and qualify the current RHEL minor, not a different OS.[93][94][98]

Red Hat’s RHEL 9 guide documents its own postgresql-server/module streams, postgresql-setup --initdb, /var/lib/pgsql/data and postgresql.service. Those are not this PGDG 18 installation or a promise of Red Hat support for upstream RPMs. Obtain any required database support separately. Keep Red Hat BaseOS/AppStream for OS dependencies, but do not mix their PostgreSQL server stream with PGDG packages.[97][100]

  1. Inspect /etc/os-release, uname -m, subscription-manager release --show, dnf repolist, dnf module list postgresql, rpm -qa 'postgresql*', systemctl list-unit-files 'postgresql*' and ss -ltn. Confirm RHEL 9.7, x86_64, valid subscribed OS repositories, free 5432 and no intended existing cluster. Inventory /var/lib/pgsql and existing units/drop-ins. Keep inbound 5432 denied. These bootstrap steps must not be applied to existing data.
  2. Use the official minor-specific repository RPM rather than pinning every OS repository through a global releasever override. Download its signing key separately, inspect its fingerprint and validate that fingerprint against the approved PGDG key record through the organization’s trust process before importing it. The commands below deliberately do not auto-approve a new key.[94][96][99]
# In an administrator-owned staging directory:
sudo dnf install curl ca-certificates gnupg2
curl --fail --show-error --location -o PGDG-RPM-GPG-KEY-RHEL \
  https://yum.postgresql.org/keys/PGDG-RPM-GPG-KEY-RHEL
curl --fail --show-error --location -o pgdg-redhat-repo.rpm \
  https://download.postgresql.org/pub/repos/yum/reporpms/EL-9.7-x86_64/pgdg-redhat-repo-latest.noarch.rpm
gpg --show-keys --with-fingerprint ./PGDG-RPM-GPG-KEY-RHEL
# Stop here until the displayed fingerprint is independently approved.
sudo rpm --import ./PGDG-RPM-GPG-KEY-RHEL
rpmkeys --checksig --verbose ./pgdg-redhat-repo.rpm
sudo dnf --setopt=localpkg_gpgcheck=1 install ./pgdg-redhat-repo.rpm

Require a valid signature from the approved key, not NOKEY or merely an HTTPS download. Never use --nogpgcheck. The inspected repository RPM is 42.0-66.rhel9.7PGDG: its pgdg18 and pgdg-common URLs explicitly contain rhel-9.7-$basearch, with gpgcheck=1, repo_gpgcheck=1 and the RHEL PGDG key. Review /etc/yum.repos.d/pgdg-redhat-all.repo, enabled repositories and candidate origins; leave testing/extras/non-free disabled unless separately approved. Preserve both package and metadata verification for these PGDG repositories; inspect other repositories separately rather than assuming identical policy.[99]

  1. On this clean host disable the distribution’s PostgreSQL module to prevent modular filtering/package mixing. Review the transaction; do not reset/switch a production module as a migration technique. PGDG documents EPEL dependencies for some packages and CodeReady Builder for GIS/development dependencies. Enable those only through approved repository/key procedures when the selected packages need them; never solve dependency errors using another RHEL minor’s RPMs or --skip-broken.[94][95]
sudo dnf module disable postgresql
sudo dnf install policycoreutils-python-utils
sudo dnf --refresh list --showduplicates postgresql18 postgresql18-server postgresql18-contrib
sudo dnf install postgresql18 postgresql18-server postgresql18-contrib
rpm -q postgresql18 postgresql18-server postgresql18-libs postgresql18-contrib pgdg-redhat-repo
/usr/pgsql-18/bin/postgres --version
/usr/pgsql-18/bin/psql --version
sudo systemctl cat postgresql-18.service

postgresql18 supplies clients; postgresql18-server supplies the server/setup/unit; postgresql18-contrib supplies modules including pg_stat_statements, amcheck, pgcrypto and basic_archive. pgAudit is separate: pgaudit_18. Record exact package NEVRAs/origins and review the whole DNF transaction before accepting it. Install a maintained approved 18.x, not an unversioned server package.[100][101][105][106]

Initialize and enter through the local socket

RPM installation does not initialize a database. The inspected PGDG setup script reads PGDATA from the named systemd unit, then calls major-18 initdb as postgres; it does not use a separate distribution cluster registry. Its current auth defaults are SCRAM with local peer, but set them explicitly. The documentation’s HOWTO contains an inconsistent major-17 path in its 18 example; use the actual packaged /usr/pgsql-18/bin/postgresql-18-setup. Check an empty target and available C.utf8 locale (locale -a) before running:[11][95][100]

sudo env PGSETUP_INITDB_OPTIONS='--encoding=UTF8 --locale=C.utf8 --data-checksums --auth-local=peer --auth-host=scram-sha-256' \
  /usr/pgsql-18/bin/postgresql-18-setup initdb

initdb creates a cluster, not merely a database; never run upstream initdb as root. The service account owns /var/lib/pgsql/18/data mode 0700. PostgreSQL 18 enables checksums by default; the option makes the choice explicit. Inspect /var/lib/pgsql/18/initdb.log, PG_VERSION and generated configuration before first start. The wrapper creates PGDATA/log; PostgreSQL logs and WAL are different.[11][100]

# /var/lib/pgsql/18/data/postgresql.conf
# memory/connection values are examples for a small host
listen_addresses = 'localhost'
port = 5432
unix_socket_directories = '/run/postgresql'
shared_buffers = '128MB'
max_connections = 50
password_encryption = 'scram-sha-256'
fsync = on
full_page_writes = on
logging_collector = on
log_directory = 'log'

Before first service startup, inspect matchpathcon /usr/pgsql-18/bin/postgres and ls -lZ /usr/pgsql-18/bin/postgres. Upstream RPM paths are not proof that the installed RHEL policy labels the executable correctly. If it lacks the required postgresql_exec_t label, have the SELinux policy owner verify that type/domain transition, add a narrow persistent mapping with semanage fcontext -a -t postgresql_exec_t '/usr/pgsql-18/bin/postgres' (only if no conflicting local record), then restorecon -v /usr/pgsql-18/bin/postgres. Do not proceed if the running service remains unconfined; keep enforcing mode and resolve the installed policy explicitly. Repeat this gate for any other major’s executable.[102]

Set the socket directory explicitly instead of relying on a compiled default that may include /tmp. PGDG’s tmpfiles rule recreates /run/postgresql as postgres:postgres mode 0755 at boot. Different ports have different socket filenames; socket permissions and peer identity remain separate controls.[100]

# /var/lib/pgsql/18/data/pg_hba.conf, ordered initial policy
local   all          postgres                         peer
local   all          all                              peer
host    all          all        127.0.0.1/32          scram-sha-256
host    all          all        ::1/128               scram-sha-256
local   replication  postgres                         peer

Keep local peer administration and local replication for backups. Do not add remote access until TLS and firewalld are ready. No trust rule or database-superuser network password is needed.[14][15]

sudo systemd-tmpfiles --create /usr/lib/tmpfiles.d/postgresql-18.conf
sudo restorecon -Rv /var/lib/pgsql/18 /run/postgresql
getenforce
sudo systemctl start postgresql-18.service
/usr/pgsql-18/bin/pg_isready -h /run/postgresql -p 5432
sudo -u postgres /usr/pgsql-18/bin/psql -X -v ON_ERROR_STOP=1 \
  -h /run/postgresql -p 5432 -d postgres

In psql inspect SELECT version();, SHOW data_directory;, SHOW config_file;, SHOW unix_socket_directories;, SHOW data_checksums; and \conninfo. Verify the intended cluster, not only “accepting connections”. Check ps -eZ shows the server’s confined postgresql_t domain and no relevant AVC denials. Then create the bounded roles/fixture. Only after acceptance run sudo systemctl enable postgresql-18.service; enablement is a separate boot decision.[73][100][102]

Operate the named service

Command Effect / interpretation
sudo systemctl show postgresql-18 -p Environment -p FragmentPath -p DropInPaths Resolve effective PGDATA, vendor unit and local overrides.
sudo systemctl status postgresql-18.service Exact default-major unit; verify SQL identity too.
sudo systemctl reload postgresql-18.service HUP reload; inspect parse errors and actual values.
sudo systemctl restart postgresql-18.service Disconnects clients; scheduled restart for startup settings.
sudo systemctl stop postgresql-18.service Packaged SIGINT fast shutdown aborts active transactions cleanly.
sudo journalctl -u postgresql-18.service --since '1 hour ago' Startup/service diagnostics; also inspect pg_current_logfile()/collector logs.

The inspected unit uses Type=notify, OS postgres, a PGDATA guard, direct postgres -D ${PGDATA}, KillMode=mixed, KillSignal=SIGINT, restart-on-failure, unlimited startup time and a one-hour stop timeout. Do not run pg_ctl alongside systemd for the same cluster or routinely kill processes. Use systemctl edit drop-ins, not edits to /usr/lib/systemd/system. RPM update scriptlets call try-restart for the default unit; updates therefore need a controlled outage and explicit validation of every separately named instance.[100]

Consider a source build only when needed

A source build is an alternative when approved RPMs cannot meet a requirement, not this production baseline. Obtain the official 18.x archive and verify the published checksum/signature; install documented compiler/library prerequisites. In the extracted source tree, as an unprivileged build account:[53]

./configure --prefix=/opt/postgresql/18 --with-ssl=openssl
make
make check
# Only after real test success and approval of this separate prefix:
sudo make install

make check starts temporary servers and must not run as root. Keep actual results. A source install supplies neither PGDG’s unit/setup script nor automatic SELinux integration; qualify executable labels/domain transitions, service supervision, extensions, patching and recovery separately before production. Never overwrite RPM-managed files or claim this alternative was tested here.[11][53][102]

Diagnose before changing authentication or files

Symptom Inspect Safe action
Service fails Journal, PGDATA/log, mounts/free bytes/inodes, unit/drop-ins Revert last change; never initialize over existing data.
Address in use ss -ltnp, socket files, unit inventory and SQL identity Find the exact competing instance, not all postgres processes.
Peer failure OS user, socket path, first local HBA match A database password does not repair OS identity.
No HBA entry Database/user/source/TLS and ordered rules Add only the intended rule, not network trust.
Permission denied namei -l PATH, ls -ldZ PATH, matchpathcon -V PATH, ausearch -m AVC,USER_AVC -ts recent Correct DAC/labels/mount access; keep SELinux enforcing.
Timeout Route, listener, active firewalld zone/provider ACL, DNS HBA cannot permit packets not reaching PostgreSQL.
Connection/memory pressure Pool budget, idle transactions, work_mem, other instances Reduce pressure before raising limits.
WAL growth Slots, archive failure, write rate Repair retention/consumer; never delete live WAL.

Use getenforce, sestatus, ps -eZ, semanage fcontext -l and semanage port -l on the actual RHEL host. policycoreutils-python-utils supplies semanage. Persistent mappings require both semanage fcontext and restorecon; chcon alone is not durable. Investigate AVC causes instead of disabling SELinux or generating an unrestricted audit2allow policy. Red Hat’s older PostgreSQL example establishes the data-label concept, not proof of this host’s current policy; inspect the installed RHEL 9 types and labels before applying custom mappings.[102][104]

SELECT sourcefile, sourceline, name, setting, applied, error
FROM pg_file_settings WHERE error IS NOT NULL;
SELECT line_number, type, database, user_name, address, auth_method, error
FROM pg_hba_file_rules ORDER BY line_number;
SELECT name, setting, source, sourcefile, pending_restart
FROM pg_settings WHERE name IN ('port','listen_addresses','shared_buffers');

A clean parse is not proof a restart setting is active. Keep local admin access while changing HBA; reload, test new allowed and denied sessions, and revert the recorded prior file if needed.[12][14][58]

Run a second cluster without crossing wires

PGDG ships one default unit per major, not an instance template or cluster-name registry. Create an explicitly named local unit for each additional instance. This example uses postgresql-18-lab2.service, /var/lib/pgsql/18/lab2, port 5542, shared /run/postgresql and its own PGDATA/log. The socket directory can be shared because port-specific filenames differ; PGDATA must never be shared.[100]

  1. Verify the path is empty, unit name unused and port free. Copy the inspected vendor unit to a new local name, preserving its notify/shutdown/user behavior, then override its data path. Do not copy an already customized primary unit inadvertently:
sudo cp /usr/lib/systemd/system/postgresql-18.service \
  /etc/systemd/system/postgresql-18-lab2.service
sudo systemctl daemon-reload
sudo systemctl edit postgresql-18-lab2.service

[Unit]
Description=PostgreSQL 18 isolated lab2
RequiresMountsFor=/var/lib/pgsql/18/lab2
[Service]
Environment=PGDATA=/var/lib/pgsql/18/lab2
  1. Run sudo systemctl daemon-reload, inspect systemctl cat and systemctl show ... -p Environment, then initialize this empty target with the same explicit options as bootstrap, passing the service name as the setup script’s second argument:
sudo env PGSETUP_INITDB_OPTIONS='--encoding=UTF8 --locale=C.utf8 --data-checksums --auth-local=peer --auth-host=scram-sha-256' \
  /usr/pgsql-18/bin/postgresql-18-setup initdb postgresql-18-lab2
  1. Edit this target’s config/HBA, not the primary’s: use the bootstrap policy, port = 5542, listen_addresses = 'localhost', unix_socket_directories = '/run/postgresql', logging_collector = on, log_directory = 'log'. Inspect SELinux’s port inventory; if 5542 is not allocated, add it as below. If another type owns it, select a different port or review that service before modifying policy. A label permits a bind; it does not open firewalld.[102]
sudo semanage port -l
# Only after confirming 5542 is available and not already labeled correctly:
sudo semanage port -a -t postgresql_port_t -p tcp 5542
sudo restorecon -Rv /var/lib/pgsql/18/lab2
sudo systemctl start postgresql-18-lab2.service
sudo -u postgres /usr/pgsql-18/bin/psql -X -h /run/postgresql -p 5542 -d postgres

Verify SHOW data_directory, port, system identifier, effective paths and ps -eZ; test clean stop/start. Do not enable a drill at boot or open its firewall. Stop postgresql-18-lab2 afterward; deleting data is a separate decision. New copied units do not automatically inherit later vendor-unit fixes: compare them after package updates and restart each instance in its approved window. Reuse this registration pattern for restore/upgrade/standby names, substituting all paths/ports; never run initdb on restored data.[100]

Distinct clusters isolate SQL namespaces and restart schedules, not CPU, disk or memory. Budget aggregate connections/buffers/workers and use resource controls/volumes as needed. A shared OS account can access all those files; use separate accounts/hosts for stronger isolation, with separately reviewed policy.

Relocate data during a clean outage

This is a stopped same-host move, not a live-copy backup. Take a verified backup; record system identifier, effective PGDATA, data_directory, config/HBA paths, external tablespaces and mounts. The destination /srv/pgsql/18/data must be empty/persistent and must not belong to another cluster.[6][22]

  1. Drain clients; sudo systemctl stop postgresql-18.service; verify no process owns the source. Create the destination with postgres:postgres, mode 0700 and traversable protected parents.
  2. Copy all of stopped PGDATA, including hidden files/configs: sudo rsync -aH /var/lib/pgsql/18/data/ /srv/pgsql/18/data/. External tablespace symlinks remain references: inventory/migrate their storage separately. Compare with sudo rsync -aHn --checksum /var/lib/pgsql/18/data/ /srv/pgsql/18/data/ and investigate differences.
  3. Preserve the data/log label distinctions with a persistent equivalence mapping, after checking no conflicting local mapping exists:[102][104]
sudo semanage fcontext -a -e /var/lib/pgsql/18/data /srv/pgsql/18/data
sudo restorecon -Rv /srv/pgsql/18/data
sudo systemctl edit postgresql-18.service

[Unit]
RequiresMountsFor=/srv/pgsql/18/data
[Service]
Environment=PGDATA=/srv/pgsql/18/data
  1. Configuration moved with PGDATA. Review absolute data_directory, HBA/includes, TLS, archive, socket and log references in both postgresql.conf and postgresql.auto.conf; they must not redirect to the old copy. Do not add a split config layout by accident. Run daemon-reload, inspect effective unit/environment, ownership, mount and matchpathcon -V labels; start only this unit.
  2. Verify SQL identity/paths, pg_current_logfile(), confined domain/no AVC denials, representative reads/writes and backup jobs before clients return. Before new writes, rollback can stop this unit and restore its prior drop-in/configs. After new writes, the old copy is stale; reconcile or perform another clean copy-back. Never start both.

Retain the original securely through the rollback window. Apply the same custom-path checks to archive/restore/tablespace directories: PostgreSQL-written data needs reviewed postgresql_db_t, external collector logs postgresql_log_t, sockets postgresql_var_run_t; validate available types on the installed policy. Persistent mappings alone do not create directories or grant Unix permissions. Keep backup-only exports accessible only to their tool accounts, not globally labeled writable by every database process.[102][104]
